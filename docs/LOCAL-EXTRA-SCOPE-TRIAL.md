# ทดลองเหตุผลและตำแหน่งของรายการเพิ่มนอกชุด

วันที่ 23 ตุลาคม 2569 · ขั้นถัดจากรายงานทบทวนมาสเตอร์ · เฉพาะ smart-boq-new ในเครื่อง

## สิ่งที่เพิ่ม

ในรายละเอียดบรรทัดวัสดุหรือค่าแรงที่เพิ่มนอกสินค้าชุด มีช่องเหตุผลและตำแหน่งที่ใช้งาน พร้อมการยืนยันจำนวนในแถวนั้นว่าเป็นเฉพาะส่วนเพิ่ม ไม่ใช่จำนวนรวมที่ต้องการทั้งงาน

- เหตุผล เช่น “SAMPLE เสริมบานพับเพื่อรับน้ำหนักนอกสเปกชุด” บังคับไม่ว่าง สูงสุด 1,000 ตัวอักษร
- ตำแหน่ง เช่น “B01 หน้าบานซ้าย ช่องที่ 2 ด้านล่าง” บังคับไม่ว่าง สูงสุด 500 ตัวอักษร
- ยืนยันหลังกรอกครบ แสดงเวลายืนยันและระบุว่าเป็นการยืนยันในเครื่อง ไม่ใช่ผู้ยืนยันจากบัญชีออนไลน์
- ใช้กับบรรทัดคิดเงินจริงนอกชุดในกลุ่ม BUY ทั้งรายการที่อาจชนกับสิ่งที่ชุดรวมแล้วและรายการที่ชุดไม่รวม เช่น ค่าติดตั้ง ส่วนวัสดุพื้นฐานของกลุ่ม MAKE ไม่ถูกบังคับให้เป็นของเพิ่มนอกชุด
- รายการต้นทุนร่วมที่ครอบคลุมกับชุดที่เปิดใช้อยู่ยังต้องตรวจเหตุผล/ตำแหน่งเช่นเดียวกัน

## การคงร่างและการยืนยันใหม่

เก็บ additionalReason, additionalLocation และ additionalConfirmation ในบรรทัดต้นทุนร่างรุ่น 3 เดิม ไม่เพิ่มตารางหรือเปลี่ยนฐานข้อมูล การยืนยันรุ่น 2 ผูกกับรหัสบรรทัด งาน กลุ่ม วิธีจัดหา รหัสวัสดุ/ประเภทแรง ขอบเขต อัตรา/ตัวหาร/ฐาน/เผื่อ เหตุผล ตำแหน่ง และชุดแม่ที่เกี่ยวข้องตาม snapshot

แก้เหตุผล ตำแหน่ง จำนวน/ฐาน/เผื่อ หรือชุดแม่แล้วต้องตรวจยืนยันใหม่ แต่ยังเก็บข้อความและจำนวนของผู้ใช้ไว้ ไม่เดาว่าของเพิ่มต้องลดหรือเพิ่มเท่าใด การคัดลอกข้อมูลยืนยันไปคนละบรรทัดใช้แทนการยืนยันใหม่ไม่ได้

ร่างเก่าที่มีเพียง checkbox/signature เดิมยังอ่านได้ ไม่ล้างราคา จำนวน หรือข้อความ แต่ยังไม่ถือว่าผ่านเงื่อนไขใหม่จนกรอกครบและยืนยันใหม่ ข้อมูลที่กรอกค้างยังบันทึกเป็นร่างได้ หากไม่ครบจะไม่คำนวณยอดที่ดูเหมือนรับรองครบแล้ว

## ตรวจย้อนกลับและสรุปซื้อ

แสดงเหตุผลและตำแหน่งในแถวต้นทางและใน “ดูที่มา” ของวัสดุสรุปซื้อ เก็บสองตำแหน่งเป็นคนละบรรทัด แม้ใช้วัสดุรหัสเดียวกัน จากนั้นรวมจำนวนซื้อเฉพาะบรรทัดคิดเงินจริงตามเดิม รายละเอียดที่รวมในชุดไม่ถูกนำมาซื้อซ้ำ

ส่งต่อเหตุผล ตำแหน่ง เวลา และแหล่งยืนยัน LOCAL_TRIAL ไปยังชีตรายละเอียดใน export Excel โดยใช้ข้อมูลผลคำนวณเดียวกัน ไม่สร้างสูตรราคาใหม่ การทดสอบรอบนี้ตรวจ metadata ในผลคำนวณ/ที่มาสรุปซื้อและชุดทดสอบ Excel เดิม ไม่ได้ตรวจรับรายงาน Excel/PDF ครบทุกหน้าแทนขั้นรายงานเต็ม

## ผลทดลอง

ทดสอบอัตโนมัติรวม 88 กรณีผ่าน และ build ผ่าน ครอบคลุม:

1. ไม่กรอก/กรอกช่องว่างในเหตุผลหรือตำแหน่งแล้วไม่ผ่านการยืนยัน
2. ข้อความเกินขนาดไม่ผ่าน และการยืนยันเก่าอย่างเดียวใช้ไม่ได้
3. แก้เหตุผลหรือตำแหน่งหลังยืนยันแล้วต้องยืนยันใหม่
4. ค่าติดตั้งที่ชุดไม่รวมก็ต้องระบุรายละเอียด ไม่เฉพาะวัสดุที่ชนขอบเขต
5. โหลดร่างกลับมาแล้วยังคงข้อความ/สถานะ รวมถึงข้อมูลค้างที่ยังไม่ครบ
6. วัสดุรหัสเดียวกันต่างตำแหน่งเก็บแยกแถว แต่รวมซื้ออย่างถูกต้อง
7. เปลี่ยนชุดแม่หรือคัดลอกข้อมูลยืนยันไปคนละแถวแล้วการยืนยันใช้ต่อไม่ได้
8. สูตรต้นทุนเดิม ค่าแรงต่อเมตร และการไม่ซื้อของที่รวมในชุดซ้ำยังผ่าน

ตรวจหน้าจอจริง: ค่าติดตั้ง LB02 ของหน้าบานเดิมกรอกเหตุผลว่าราคาชุดไม่รวมติดตั้ง และตำแหน่งทั้งชุด 3.50 เมตร; เพิ่ม H01-SAMPLE 1 ตัวพร้อมเหตุผล/ตำแหน่งเฉพาะ สรุปซื้อได้บานพับเพิ่ม 1 ตัว ส่วนบานพับอ้างอิงในชุด 4 ตัวไม่ถูกซื้อซ้ำ เปลี่ยนตำแหน่งแล้วระบบรอยืนยันใหม่ โหลดใหม่ข้อความยังอยู่

ตัวอย่างหลังยืนยัน: DOOR ชุด 2,000 + ติดตั้ง 2,100 + บานพับเพิ่ม 100 = 4,200 บาท หรือ 1,200 บาท/เมตร เป็น SAMPLE เพื่อทดสอบ ไม่ใช่ใบเสนอราคา

## ข้อจำกัดที่ยังมีผล

ตำแหน่งรอบนี้เป็นข้อความในบริบทกลุ่มงาน ไม่ใช่ทะเบียนตำแหน่งที่มีรหัสและกฎตรวจช่วงซ้อนกันอัตโนมัติ เหตุผลมาจากผู้กรอก ยังไม่มีผู้ตรวจรับหรือหลักฐานผู้ขายผูกไฟล์ การยืนยันเก็บเฉพาะสถานะ/เวลาล่าสุดในเครื่อง ไม่ใช่ประวัติแก้ไขถาวรหรือบันทึกที่ป้องกันการแก้จากภายนอก

ยังต้องทำ coverage และการตรวจขอบเขต/ตำแหน่งเต็มรูปแบบบน server พร้อมผู้ยืนยันจาก session, transaction, version, RLS และ lock ก่อนรับรองงานจริง ห้ามถือว่า local confirmation ผ่านเกณฑ์เหล่านั้นแล้ว

ไม่แก้ฐานจริง ไม่เปลี่ยน migrations/RPC ไม่เผยแพร่เว็บ และไม่เปลี่ยนจำนวน 18 ตารางในแบบ
