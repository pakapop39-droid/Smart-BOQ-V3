# ทดลองคำนวณทันทีในเครื่อง — 23 ตุลาคม 2569

สถานะล่าสุด: Master 1.9 เพิ่ม [บันทึกอัตโนมัติในเบราว์เซอร์](LOCAL-AUTOSAVE.md) แล้ว ข้อความเก่าเรื่องรีเฟรชคืนตัวอย่างเป็นประวัติก่อนปรับรุ่นนี้

เจ้าของขอให้แก้หน้าจอและเห็นผลเมื่อแก้ตัวเลข โดยทดลองในเครื่องก่อน รอบนี้ไม่ deploy และไม่เปลี่ยนฐานข้อมูล

เปิด http://127.0.0.1:5177/ ขณะ dev server ทำงาน เปิดต้นทุน S001 แล้วเปลี่ยนปริมาณใช้ตั้งต้น PN01 จาก 1.5 เป็น 2 จะเห็นใช้รวม 7 แผ่น ต้นทุน 7,000 บาท และต้นทุนตู้ 19,950 บาททันที

เพิ่มปริมาณใช้รวม ต้นทุนต่อหน่วยใช้ ต้นทุนรวมรายแถว และสรุปงานที่เลือก เปลี่ยนชื่อฐานปริมาณเป็นภาษาไทย กรอกไม่ครบจะแสดงข้อผิดพลาดและล้างยอดที่ใช้ไม่ได้ ไม่บันทึกข้อมูล

ใช้ lib/live-calculator.mjs สำหรับผลตอบสนองทันทีด้วย decimal.js ความละเอียด 80 หลัก ตามกฎของ SQL เดิม กำไรจากราคาขาย ปัดราคาขายต่อหน่วยก่อนคูณปริมาณ และรวมต้นทุนก่อนปัดระดับงานย่อย ปุ่มตรวจยอดกับ InsForge เรียก RPC เดิมแบบไม่บันทึก ไม่แก้ฟังก์ชันบนคลาวด์

ตรวจ npm test 11 กรณี, build, browser เปลี่ยนปริมาณ/ค่าว่าง/คืนค่าถูกต้อง และตรวจยอดกับ InsForge ในเบราว์เซอร์ ส่วน scripts/check-live-parity.mjs เทียบต้นทุน ราคาขาย งบซื้อ ค่าแรง และยอดรวมที่แสดง ในสองวิธีผลิตทั้งค่าตั้งต้นและค่าที่แก้ รวม 4 ชุด ดู artifacts/live-parity.json

ข้อจำกัด: เป็นผลทดลองในเครื่อง ไม่รับรองเลขทศนิยมทุกกรณีแทน PostgreSQL ไม่แสดง purchase_excess ในเครื่อง เพราะพบว่าการปัดค่ากึ่งสตางค์จากผลหารซ้ำอาจต่าง PostgreSQL 0.01 บาทในข้อมูลแก้ตัวอย่าง ฟิลด์นี้ไม่ได้ใช้ในหน้าจอหรือ Excel เดิม ยังคงตรวจยอดที่แสดงกับ InsForge ได้ และต้องขยายการตรวจกรณีขอบก่อนใช้งานจริง

ไม่มีการเปลี่ยนสูตรวัดพื้นที่ เผื่อเศษเริ่มต้น ขนส่ง หรือกฎธุรกิจใหม่ ระบบเดิมและมาสเตอร์ต้นฉบับไม่เปลี่ยน


## เพิ่ม/ลบต้นทุนและเลิกทำ — 23 ตุลาคม 2569

เจ้าของอนุมัติปุ่มเพิ่มจากคลังตัวอย่างและลบแถวพร้อมเลิกทำ ทำเฉพาะในเครื่อง แต่ละ S001–S004 มีประวัติการลบแยกกัน เลิกทำได้ทีละรายการล่าสุด คืนตำแหน่งและค่าที่กรอกเดิม ไม่แก้คลังกลาง ตัวเลือกเพิ่มแสดงวัสดุ ค่าแรง และ VS Modular ที่ยังไม่มีในงานนั้น กันเพิ่มรหัสซ้ำ และไม่ให้ใส่ ST01 ในต้นทุนตู้

เมื่อเพิ่ม แถวตั้งต้นปริมาณ 1 หาร 1 เศษ 0% ใช้ต่อหน่วยขาย ยกเว้น VS Modular ใช้จำนวนเต็มรวมทั้งรายการ และ LM01 งานตู้คงค่าพื้นที่ที่กรอกและฐานรวมทั้งรายการ ผู้ใช้แก้ก่อนใช้ผลจริงได้ การสลับวิธีผลิตหรือคืนค่าตัวอย่างจะล้างประวัติของตารางที่ถูกคืนค่า

ลบหมดได้ ยอดงานเป็นศูนย์พร้อมป้ายร่างยังไม่ครบ ปิดส่งออก/พิมพ์และไม่ให้ตรวจ RPC จนทุกงานมีต้นทุน เพราะ RPC เดิมไม่รับตารางว่าง ไม่ถือว่าต้นทุนศูนย์ผ่านตรวจแล้ว หากเพิ่มรหัสที่ลบกลับเองแล้วต้องลบแถวใหม่ก่อนเลิกทำแถวเก่า เพื่อไม่สร้างซ้ำ

ทดสอบผ่าน 14 กรณีและ build ผ่าน ตรวจเบราว์เซอร์จริง: ลบ/คืน PN01, เพิ่ม LB06 ยอดตู้เพิ่ม 1,400 บาท, ลบ/คืน LM01 ไม่เกิดข้อผิดพลาด, ลบ/คืนรายการเดียวของ S002 แสดงศูนย์และกลับมาคำนวณได้ ระบบเดิม 509 ไฟล์และมาสเตอร์ต้นฉบับไม่เปลี่ยน
