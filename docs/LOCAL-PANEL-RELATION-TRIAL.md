# ทดลองตารางกลุ่มแผงและวัสดุแยกบรรทัดในเครื่อง

> **แบบ relation ล่าสุดสำหรับทบทวน: [รายการงาน/ชุด 18 ตาราง](RELATION-18-WORK-SETS.md)** เลือกซื้อสำเร็จรูปหรือผลิตเองแยกแต่ละชุด และไม่คิดวัสดุที่รวมมาในชุดซ้ำ แบบแผง 17 ตาราง/โค้ดทดลองที่อธิบายด้านล่างเป็นฉบับก่อนการทบทวนนี้ รอบปัจจุบันเปลี่ยนเฉพาะเอกสาร ฐานออนไลน์ยัง 16 ตาราง และยังไม่แก้โค้ดให้รองรับแบบชุดใหม่


วันที่ 23 ตุลาคม 2569 · โค้ดทดลองใน smart-boq-new · ไม่มีการเปลี่ยนฐานข้อมูลจริง

## วิธีทดลอง

เปิด http://127.0.0.1:5177/ → ประมาณราคา → เปิดต้นทุน S001 → CUSTOM ผลิตเอง จะเห็นตาราง BODY แผงตัวตู้ และ DOOR แผงหน้าบาน กรอกพื้นที่ด้านเดียวและจำนวนด้านที่ตารางกลุ่ม กดเปิดวัสดุของแถวใด จะเปิดตารางวัสดุเฉพาะกลุ่มนั้นด้านล่าง กดแถวอื่นเปลี่ยนบริบทโดยไม่ล้างข้อมูล กดซ้ำหรือปิดตารางวัสดุเพื่อยุบได้

เลือกรหัสไม้อัด/ลามิเนตในแถววัสดุ กรอกอัตราไม้โครงเป็นเมตรต่อ ตร.ม. และกรอกพื้นที่ครอบคลุมกาวเป็น ตร.ม.ต่อลิตรในแถวกาว อัตราเริ่มว่าง ไม่กำหนดค่าจริงให้เอง เผื่อเศษและราคาที่ใช้แก้แยกแต่ละบรรทัดได้ ค่าแรง/อุปกรณ์รวมตู้เปิดจากแถวต้นทุนตรง ไม่บังคับให้อยู่ในกลุ่มแผง สเปกและราคาทั้งหมดเป็น SAMPLE

## การเก็บข้อมูลในร่าง

- groups เก็บพื้นที่ด้านเดียว จำนวนด้าน เปิด/ปิดใช้ และเจ้าของงาน ไม่เก็บรหัสไม้อัด/ลามิเนตหรืออัตราไม้โครง/กาวซ้ำบนกลุ่ม
- แต่ละบรรทัดวัสดุมี costLineId UUID, componentId, componentGroupId, lineRole, quantitySource และ projectResourceId ของตัวเอง
- projectResourceId ใช้รหัสทรัพยากรที่ไม่ซ้ำในโครงการทดลองเป็น local reference key; BODY/DOOR เป็น local group IDs ยังไม่ใช่ FK ของฐานออนไลน์ การพัฒนาฐานต้อง map เป็น UUID ตามเอกสาร relation
- เก็บ numerator/denominator เป็นอัตราของบรรทัด ไม่เก็บพื้นที่คำนวณแล้วซ้ำ ปริมาณใช้เกิดจากฐานพื้นที่กลุ่ม × อัตรา × เผื่อเศษ ไม่คูณเมตรขายซ้ำ
- บรรทัดเก็บราคา/yield/หน่วย/ประเภท/ชื่อ snapshot จากทรัพยากรที่เลือก การเปลี่ยนสเปกปรับเฉพาะบรรทัดนั้น การแก้ราคาอ้างอิงในคลังทดลองไม่เปลี่ยนราคาที่เก็บในกลุ่มเดิมอัตโนมัติ ถ้าขนาดบรรจุหรือหน่วยไม่ตรงจะหยุดให้ตรวจ ไม่รวมต่างสเปกเป็นวัสดุเดียว
- กลุ่มที่ปิดใช้ยังเก็บวัสดุและ inputs ไว้ แต่ไม่นำมาคำนวณ บรรทัดลามิเนต/กาวยังจำสเปกไว้เมื่อเลือกปิดลามิเนต 0 ด้าน โดยไม่นำมาคิดใช้
- ร่างใช้ schemaVersion 2 ใน localStorage key ของโครงการเดิม ข้อมูลขาด/ผิดยังเก็บร่างได้แต่ไม่แสดงผลพร้อมใช้ หน่วยความหมายที่ขัดกันหรือ reference ผิดถูกปฏิเสธ
- ขณะสลับไป VS Modular เก็บร่างวัสดุ CUSTOM แยกไว้ กลับ CUSTOM แล้วคืนบรรทัดเดิมพร้อมราคา/อัตรา/ID ไม่ส่งกลุ่มไป RPC เดิม

## ร่างรุ่นเก่า

ไม่เขียนทับร่างแบบแถวรวมโดยอัตโนมัติ ปุ่มตรวจและแปลงร่างแสดงวัสดุ อัตรา เผื่อเศษ และราคาอ้างอิงแยกตามกลุ่มก่อนใช้ อ้าง inputs พื้นที่/จำนวนด้าน/สเปกเดิม ไม่แบ่งยอดรวมด้วยการเดา ราคาและตัวแปลงมาจากทรัพยากรในร่างเดิมโดยระบุที่มาในหน้าตรวจ

ถ้ารหัสเดียวใช้หลายกลุ่มและแถวรวมมีเผื่อเศษไม่ใช่ 0 จะเว้นเผื่อเศษใหม่ให้ตรวจทีละกลุ่ม ไม่คัดลอกอัตราที่ไม่ทราบการแบ่งให้เอง ร่างต้นฉบับเก็บหนึ่งครั้งใน key smart-boq-new-test:before-panel-relation-v2 และดาวน์โหลดสำเนา JSON ผ่านปุ่มในแถบบันทึกร่างได้ ถ้าเก็บสำเนาไม่สำเร็จจะไม่แปลง ประวัติลบ S001 เริ่มใหม่หลังแปลง ตารางอื่นและคลังเดิมคงข้อมูลเดิม

สำเนาก่อนแปลงคงอยู่เมื่อคืนค่าร่างปัจจุบัน เพื่อให้ยังดาวน์โหลดได้ ไม่ล้าง localStorage ของแอปอื่น

## การรวมยอดและผลส่งออก

เครื่องคำนวณอ่านแต่ละ costLineId แยกกัน ไม่รวมรหัสวัสดุเป็นบรรทัดต้นทุนเดียว ต้นทุนกลุ่มรวมเพื่อแสดงผล ต้นทุน S001 รวมทุกบรรทัดที่เปิดใช้กับต้นทุนตรงครั้งเดียวก่อนปัด ยอดกลุ่มที่แสดงสองตำแหน่งจึงอาจรวมต่างยอด S001 อยู่ 0.01 บาท มีข้อความอธิบายในหน้า ไม่เปลี่ยนกติกาการปัดเพื่อบังคับยอดแสดงให้ตรงกัน

สรุปซื้อรวมปริมาณหลังเผื่อเศษของรหัสทรัพยากรเดียวกันทั้งโครงการก่อน CEILING จำนวนซื้อ แสดงที่มา S001/BODY, S001/DOOR, S003 ต้นทุนตรงได้ ไม่เปลี่ยนข้อมูลต้นทาง งบซื้อใช้ราคาอ้างอิงของโครงการ ขณะที่ต้นทุนใช้จริงใช้ราคาบรรทัดที่เก็บไว้ ค่าแรงไม่ปัดเป็นวัสดุซื้อ

Excel ผลประมาณราคาเพิ่มชีตต้นทุนแยกกลุ่ม SAMPLE ให้เห็นกลุ่ม รหัสบรรทัด รหัสวัสดุ ใช้รวม ราคาที่ใช้และต้นทุน ส่วนชีตงบซื้อยังรวมต่อรหัสเดิม ไม่มีการ Import ข้อมูลกลุ่มเข้าออนไลน์

## การตรวจรอบนี้

- npm test ผ่าน 51 กรณี รวมวัสดุรหัสเดียวสองบรรทัด ราคา/เผื่อเศษแยกกลุ่ม การรวมซื้อก่อนปัด การไม่คูณเมตรขาย กลุ่มปิดใช้ กลุ่มไม่มีปิดผิว ลบ/เลิกทำ อ้างกลุ่มผิดงาน ร่าง schema 2 และการเก็บสำเนาก่อนแปลง
- npm run build ผ่าน มีคำเตือนเดิมจาก SDK เรื่อง browser external crypto
- ตรวจเบราว์เซอร์จริง: preview และแปลงร่างเดิม เปิดสลับกลุ่ม เลือก PLY01 ร่วมกัน กำหนดเผื่อเศษหน้าบาน 5% แล้วตัวตู้ยัง 0%; ลบ PLY01 ของตัวตู้ขณะหน้าบานยังใช้รหัสเดียวกันและเลิกทำได้; แก้ราคาตัวตู้ 600 แล้วหน้าบานยัง 500; รีเฟรชแล้ว ID และค่าต่างกันยังอยู่; สลับ VS Modular และกลับ CUSTOM รักษาข้อมูลเดิมได้
- ตัวอย่างกรณีเผื่อเศษข้างต้นใช้ 20 + 6.3 + 6 = 32.3 ตร.ม. ของ PLY01 สรุปซื้อ 12 แผ่นตามขนาด SAMPLE 2.88 ตร.ม. ราคาที่กรอกเพื่อทดสอบไม่ใช่ราคาจริงหรืออัตรามาตรฐาน
- ไม่พบ console error ในขั้นตอนที่ตรวจ ยังไม่อ้างว่าทดสอบฐาน relation 17 ตารางแล้ว

ข้อจำกัด: UI ยังมีสองกลุ่มตามคำขอ บทบาทวัสดุหลักอย่างละหนึ่งบรรทัดต่อกลุ่ม การเพิ่มต้นทุนเพิ่มเติมทำในต้นทุนตรง; ค่าแรง/งานขอบและข้อมูลจริงยังต้องตรวจให้ครบ Backend, RLS และ lock ของ relation ใหม่ยังไม่ทำ ฐานจริงคงเดิม 16 ตารางธุรกิจ ไม่มี SQL/migration/RPC หรือ deployment ในรอบนี้
