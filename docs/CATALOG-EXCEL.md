# Excel สำหรับแก้คลังและนำกลับ — แบบสำหรับเฟส 2

ขอบเขตที่เจ้าของยืนยัน: วัสดุ ค่าแรง และ VS Modular เท่านั้น ไม่รวมโครงการ Keyplan งานย่อย และรายการต้นทุนโครงการ เอกสารนี้ขยาย Master 1.6 สถานะการสร้างและทดสอบจริงดู [รายงานเฟส 2](PHASE-2-REPORT.md) ชีตวัสดุรองรับประเภท MATERIAL/EQUIPMENT ค่าแรงเป็น LABOR ส่วน VS Modular แยกตามรายละเอียดสินค้า ไม่ส่งออกรายการซ้ำ

## รูปแบบไฟล์ที่เรียบง่าย

หนึ่งไฟล์ .xlsx มีชีตคำแนะนำและชีตข้อมูลสามชุด: วัสดุ, ค่าแรง, VS Modular แต่ละรายการปรากฏเพียงชีตเดียว แถว VS Modular ประกอบด้วยข้อมูลทะเบียนต้นทุนและรายละเอียดโมดูลาร์ในแถวเดียว ไม่ต้องให้ผู้ใช้เชื่อมตารางเอง ระบบไม่ export รายการเดียวกันซ้ำในชีตวัสดุ

หัวคอลัมน์เป็นภาษาไทยและมีรหัสช่องคงที่ประกอบ เพื่อให้ตรวจรูปแบบได้ รุ่นแม่แบบ template_version เป็นข้อมูลกำกับไฟล์ ไม่เป็นตารางธุรกิจใหม่ รหัสประเภทต้นทุน หน่วย และวิธีแปลงใช้ค่าจากระบบพร้อมคำอธิบาย ไม่ให้ import สร้างหน่วย/ประเภทใหม่จากคำสะกดเอง

| กลุ่มช่อง | ฟิลด์และวิธีใช้ |
|---|---|
| ตัวตนจากระบบ | resource_id (UUID), version (BIGINT) ส่งออกเป็นข้อความและล็อกเซลล์เพื่อช่วยป้องกันแก้พลาด แต่ server ต้องตรวจซ้ำ; แถวใหม่เว้นทั้งคู่ |
| ข้อมูลแก้ได้ | resource_name, specification, purchase_unit_price, price_updated_at, is_active และข้อมูลหน่วย/การแปลงที่ตรงสเปกเดิมตาม Master |
| รหัสรายการ | resource_code เป็นข้อความ เก็บเลขศูนย์นำหน้า รหัสเต็มและขีดกลาง; แถวเดิมห้ามเปลี่ยนรหัส แถวใหม่ต้องระบุรหัสไม่ซ้ำ |
| ประเภท/หน่วย | cost_type_code, purchase_unit_code, usage_unit_code อ้างรหัสที่มีอยู่ ตรวจว่าถูกประเภทชีต; VS Modular ต้องมีรายละเอียดครบตาม Master |
| ตัวแปลง | conversion_method, pack_count, length_m, width_m, volume_l, purchase_increment, coverage_area_per_purchase, coverage_note ตามเงื่อนไขของวิธีแปลงเดิม |
| เพิ่มสำหรับ VS Modular | function_code, width_mm, height_mm, depth_mm, led_code, included_scope, excluded_scope, index_reference; ราคามีช่องเดียว ไม่เพิ่มราคาใน modular_products |
| ไม่ให้แก้ผ่านไฟล์ | company_id, created_at, updated_at, yield ที่ระบบคำนวณ และยอดรวม/สถานะยืนยันราคาหรือขอบเขตของโครงการ |

แถวเดิมส่งออกพร้อมค่าครบ ไม่ใช่ไฟล์ patch: ช่องเลือกกรอกที่ว่างหมายถึงล้างค่านั้น ช่องบังคับว่างเป็นข้อผิดพลาด ชีตคำแนะนำต้องบอกกติกานี้ชัดเจน ไม่ตีความช่องว่างเป็นศูนย์ วันที่ใช้ YYYY-MM-DD ตามเขตเวลาระบบ ตัวเลขเป็นค่าตัวเลขจริงไม่รวมสัญลักษณ์เงิน ไม่ให้สูตร Excel/macros/ลิงก์ภายนอกเป็นข้อมูลนำเข้า ข้อความที่ขึ้นต้นเครื่องหมายสูตรต้องส่งออกเป็นเซลล์ข้อความ ไม่ให้ Excel ประมวลผลเป็นสูตร

การเปลี่ยนหน่วย/ขนาด/ตัวแปลงจนเป็นคนละสเปกกับรหัสเดิมต้องแจ้งให้ใช้รหัสใหม่ ไม่ตีความเป็นการอัปเดตราคาอย่างเดียว การนำเข้าข้อมูลโมดูลาร์ต้องตรวจรหัสเต็มกับขนาดและ LED ตามกฎเดิม ไม่เดาชื่อฟังก์ชันจาก Index ที่ยังไม่ยืนยัน

## ฐานข้อมูลที่เตรียมไว้ตั้งแต่เฟสนี้

คงทะเบียนเดียวใน cost_resources และรายละเอียด 1:1 ใน modular_products ไม่เพิ่มสำเนาราคา ไม่เพิ่มตาราง import เพื่อเก็บข้อมูลทดลองถาวร ทั้งหมดเป็นแบบ ยังไม่รัน migration

| จุดปรับ | แบบข้อจำกัด |
|---|---|
| version ของคลัง | cost_resources.version BIGINT NOT NULL DEFAULT 1 CHECK (version > 0); เพิ่ม 1 เมื่อเนื้อหาที่แก้ได้เปลี่ยนจริง ไม่เพิ่มเมื่อ import ซ้ำแบบไม่เปลี่ยน |
| เวลาระบบ | cost_resources.created_at, updated_at TIMESTAMPTZ NOT NULL กำหนดโดย server; price_updated_at ยังเป็นวันที่ราคา ไม่ใช้แทน version |
| กันรหัสซ้ำ | UNIQUE(company_id, resource_code) เดิม พร้อม canonical key ที่ normalize Unicode NFC ตัดช่องว่างหัวท้ายและเทียบอักษรละตินไม่สนตัวพิมพ์; unique expression index ใช้กฎเดียวกับทุกช่องทางเขียน เก็บรหัสแสดงผลเดิม |
| สิทธิ์ | resource_id ต้องอยู่บริษัทของ session; ไม่รับ tenant จากไฟล์ FK ไปหน่วย/ประเภทต้องเป็นข้อมูลอ้างอิงที่อนุญาต ไม่มีการย้ายเจ้าของหรือย้ายแถวข้ามบริษัท |
| โมดูลาร์ | modular_products.resource_id PK/FK เดิม ไม่มี version แยก; เปลี่ยนรายละเอียดใดต้องล็อกและเพิ่ม version ของ cost_resources แม่ด้วยใน transaction เดียว |
| ไม่แก้ข้อมูลย้อนหลัง | ไม่ cascade การเปลี่ยนราคา/สเปกไป project_resources หรือ component_cost_lines ที่มี snapshot อยู่แล้ว |

canonical key เป็นรายละเอียดทางเทคนิคกันรหัสที่ต่างเพียงช่องว่าง/ตัวพิมพ์ ไม่รวมรหัสที่ต่างขีดกลาง เลขศูนย์ หรือสเปกเข้าด้วยกัน และไม่แก้รหัสเก่าข้ามบริษัท หากข้อมูลเดิมชนกันต้องรายงานก่อนการย้าย ไม่รวมแถวให้เอง

## การจับคู่โดยไม่ซ้ำ

1. ถ้ามี resource_id: หาได้เฉพาะบริษัทปัจจุบัน รหัสรายการและชนิดชีตต้องตรงของเดิม ID ไม่พบ/ผิดบริษัทให้ปฏิเสธ ไม่เปลี่ยนเป็นแถวใหม่
2. ถ้าเนื้อหาที่แก้ได้ตรงฐานข้อมูลปัจจุบันทั้งหมด: เป็น NO_CHANGE แม้ version เก่า เพื่อให้นำไฟล์เดิมเข้าซ้ำได้ ไม่มีผลต่อเวลา/รุ่นข้อมูล
3. ถ้าเนื้อหาต่าง: ต้องมี version เท่าปัจจุบัน มิฉะนั้นเป็น CONFLICT ให้ export ใหม่ก่อน ไม่ใช้เวลาที่แก้ไฟล์หรือราคาเป็นเกณฑ์ทับ
4. ถ้าเว้น ID/version: ค้นรหัสภายในบริษัท ถ้าไม่มีจึงเป็น ADD ถ้ามีและเนื้อหาตรงเป็น NO_CHANGE ถ้ามีแต่เนื้อหาต่างเป็น MATCH_REVIEW ให้ export รายการปัจจุบันแล้วแก้ด้วย ID/version ไม่ทับรายการเดิมโดยไม่มีฐานรุ่น
5. ห้าม ID หรือ canonical code เดียวกันซ้ำในไฟล์/ข้ามชีต ให้ชี้ทุกแถวที่ชนกัน ไม่เลือกแถวท้ายชนะอัตโนมัติ
6. แถวที่ไม่อยู่ในไฟล์คงเดิม ไม่มี hard delete โดย import; is_active=false หยุดการเลือกใช้ใหม่โดยไม่ลบประวัติ

## ก่อนและขณะบันทึก

หน้าจอแสดง ADD / UPDATE / NO_CHANGE / ERROR / CONFLICT พร้อมชีต เลขแถว ช่องที่ผิด และค่าเดิม→ใหม่ ไม่เริ่มเขียนระหว่างอ่านไฟล์ ผู้ใช้แก้ไฟล์ที่ผิดแล้วตรวจใหม่ก่อนยืนยันทั้งชุด ไม่ข้ามแถวผิดอัตโนมัติ

เมื่อยืนยัน server อ่านชุดข้อมูลที่ตรวจอีกครั้ง ตรวจสิทธิ์และ version ใหม่ภายใน transaction ล็อกแถวแม่ตามลำดับ resource_id คงที่ ป้องกัน deadlock; INSERT อาศัย unique index กันการเพิ่มพร้อมกัน หากมีการเปลี่ยนระหว่าง preview กับยืนยันให้ rollback ทั้งชุดและรายงานตรวจใหม่ ห้ามใช้ upsert ที่ทับโดยไม่ตรวจ version

ถ้ายืนยันสำเร็จแต่เครือข่ายขาดแล้วส่งชุดเดิมซ้ำ: ค่าที่ตรงปัจจุบันเป็น NO_CHANGE จึงไม่สร้างแถวหรือเพิ่ม version ซ้ำ หากมีคนเปลี่ยนค่าระหว่างนั้นต้อง CONFLICT และไม่ทับ ชุดแก้โมดูลาร์กับแม่ต้อง commit/rollback พร้อมกัน ไม่มีรายการกำพร้า

ไฟล์อยู่เฉพาะงานนำเข้าของผู้ใช้ ไม่เก็บ Excel หรือ raw rows ถาวรในฐานใช้งานโดยไม่จำเป็น กำหนดขนาดไฟล์/จำนวนแถวและการหมดอายุ preview เป็นค่าทางเทคนิคที่ทดสอบในระบบทดลองก่อนใช้งานจริง ไม่ใช้ version ของไฟล์แทนการตรวจฐานข้อมูล

## เกณฑ์ตรวจรับก่อนนำข้อมูลจริงเข้า

| กรณีทดสอบ | ผลที่ต้องได้ |
|---|---|
| Export แล้ว import โดยไม่แก้ | จำนวนและ version ไม่เปลี่ยน |
| แก้ราคาวัสดุ/ค่าแรง/โมดูลาร์แล้วนำเข้า | แก้แถวเดิม ID คงเดิม รุ่นเพิ่มครั้งเดียว ราคามีแห่งเดียว |
| นำไฟล์ที่เพิ่งสำเร็จเข้าซ้ำ | ไม่เพิ่มรายการหรือรุ่นซ้ำ |
| เพิ่มรหัสใหม่หนึ่งแถว แล้วนำไฟล์นั้นซ้ำ | เพิ่มเพียงหนึ่งรายการ |
| รหัสซ้ำ/ต่างตัวพิมพ์/ช่องว่าง/ซ้ำข้ามชีต | แจ้งชนกัน ไม่สร้างแถวซ้ำ |
| รหัสมีศูนย์นำหน้าหรือรหัสโมดูลาร์เต็ม | round-trip คงรหัสเป็นข้อความครบ |
| ID บริษัทอื่น, ID ปลอม, เปลี่ยนรหัสเดิม | ปฏิเสธ ไม่เปิดเผยข้อมูลบริษัทอื่น |
| ไฟล์เก่าแก้ราคา/ข้อมูลเปลี่ยนระหว่าง preview | conflict ทั้งชุด ไม่ทับงานใหม่ |
| แถวหายจาก Excel | ไม่มีการลบ |
| ตัวแปลง/หน่วย/ขนาด LED ผิด หรือสูตร Excel | แจ้งชีต/แถว/ช่อง ไม่เขียนข้อมูล |
| โมดูลาร์ครึ่งหนึ่งบันทึกไม่ผ่าน | rollback ทั้งแม่และลูกพร้อมรายการอื่นในชุด |
| Import ราคาคลังเมื่อมีโครงการเดิม | snapshot และโครงการที่ล็อกไม่เปลี่ยน |

นี่เป็นเกณฑ์ทดสอบที่ต้องทำในเฟส 2 และหน้าจอนำเข้ารุ่นแรก ยังไม่ได้อ้างว่าทดสอบกับ InsForge จริงแล้ว


## แม่แบบ 2 สำหรับคลังแท็กในเครื่อง

ดู [CATALOG-TAGS-LOCAL.md](CATALOG-TAGS-LOCAL.md) สำหรับพฤติกรรมล่าสุด แม่แบบ 2 เพิ่มแท็กงาน [tags] ท้ายทั้งสามชีต แยกด้วยขึ้นบรรทัดใหม่ ช่องว่างล้างแท็ก แม่แบบ 1 ยังอ่านได้และคงแท็กเดิม ใช้ไฟล์เดียวกับคลังตัวอย่างกลาง ส่งออกเฉพาะที่เลือกได้

Import ตรวจรหัส/รุ่นข้อมูลและแสดงรายละเอียดก่อน–หลัง รวมชื่อแท็กใหม่ก่อนยืนยัน ใช้เฉพาะคลังในหน่วยความจำ ไม่ปรับ snapshot งานเดิม ไม่มีการส่งแม่แบบ 2 เข้า RPC ฐานในรอบนี้ การขยายตารางแท็ก/ความสัมพันธ์และ API จริงยังเป็นงานรอบถัดไป


### สถานะ 1.9

คลังที่ Import และแท็กบันทึกอัตโนมัติในเบราว์เซอร์แล้ว ดู [LOCAL-AUTOSAVE.md](LOCAL-AUTOSAVE.md) ยังไม่ส่ง Import เข้าฐานออนไลน์และไม่อัปเดตราคา snapshot งานเดิม
