# Smart BOQ V3 — บัญชีงานตกค้าง
วันที่ 23 ตุลาคม 2569 · อ้าง MASTER 2.0 · งานค้างไม่ใช่การอนุมัติให้เชื่อมออนไลน์

## 1. ทำแล้วและไม่ต้องทำซ้ำ
มี SQLite 22 ตาราง คลังทำราคาต่อหน่วย/รุ่น READY→สำเนาโครงการ บันทึกจากโครงการเป็น DRAFT รหัส RT อัตโนมัติ แผง/ชุด BUY/MAKE แยกกลุ่ม คง snapshot ของในชุดไม่คิดซ้ำ สรุปซื้อข้าม Keyplan Excel คลังและ backup ในเครื่อง มีชุดทดสอบล่าสุด 125 cases ผลนี้ไม่ปิดงานต่อไปนี้

## 2. ต้องเติมในแอปหลักก่อน — งาน local
| รหัส | งานค้าง/ข้อเท็จจริง | ผลส่งมอบและเกณฑ์จบ |
|---|---|---|
| L01 | แท็กใน SQLite ยังเป็นข้อความ ไม่มีทะเบียนรหัสแท็กและจัดการแท็กแบบต้นแบบ | ทำทะเบียน/ผูกหลายแท็ก ย้ายข้อความเดิมโดย preview ไม่ลบ ไม่เดาจากชื่อสินค้า เพิ่ม/แก้ชื่อ/รวม/ลบเฉพาะแท็ก ใช้ข้ามสามคลังได้ |
| L02 | คลังหลักมีค้นหา แต่ไม่มี OR filter แท็กและ bulk actions ครบ | แยกมุมมองวัสดุ/ค่าแรง/VS Modular แสดงจำนวน เลือกทั้งหมดเฉพาะที่เห็น เปลี่ยน filter ล้าง selection เพิ่ม/เอาแท็กออกหลายรายการ/ส่งออกที่เลือก |
| L03 | การเลือกเข้าต้นทุนและลบยังไม่มี workflow หลายรายการพร้อม undo เท่าต้นแบบ | picker ค้นหา/กรอง/ติ๊กหลายรายการ เพิ่มอย่าง atomic; ลบหลายแถวพร้อมคืนทั้งชุดและ snapshot; รหัสที่เพิ่มแล้วไม่สร้างซ้ำโดยไม่ได้ตั้งใจ |
| L04 | ไม่มี undo การลบใน local API/SQLite | undo แบบ persistent ของการลบต้นทุน/แท็ก ทดสอบหลัง refresh/reopen, FK/reference/coverage, version conflict และ rollback ไม่มีการคืนฐานทั้งหมดทับการแก้อื่น |
| L05 | Excel แม่แบบ 1/2 ใช้ได้บางส่วน แต่แท็กหลักยังเป็นข้อความ และข้อมูล Modular/ชุดไม่ครบ round-trip ทั้งหมด | เทียบ export→import ทุกช่อง รวม tag rename/merge, IDs/version, missing row, no-op, conflict, unknown tag preview และการเก็บ snapshot; ไม่อ้างว่ารวมของในชุดครบเพราะมีชีต VS |
| L06 | backup ปัจจุบันรองรับ 18/22 ตาราง ยังไม่มีโครงสร้างแท็กใหม่/undo | ออกแบบรุ่น backup ใหม่เมื่อเปลี่ยน schema, รับไฟล์เก่า, backup ก่อนย้าย/restore และตรวจยอดเดิม; ห้ามเปลี่ยนตัวตนหรือ sync คลังไปโครงการ |
| L07 | เปลี่ยนต้นแบบที่โครงการเดิมใช้อยู่แบบเปรียบเทียบยังไม่มี | preview รุ่นเก่า→ใหม่ แสดงหน่วย/ปริมาณ/รายการปรับเฉพาะ/ราคา/ขอบเขตก่อนยืนยัน ไม่เปลี่ยนเงียบและไม่อัปเดตอัตโนมัติ |
| L08 | ข้อมูลรายช่องตามสัญญาเดิมยังไม่เท่ากับฟอร์ม local ทั้งหมด | ทำ field mapping จาก DATA-REQUIREMENTS ไป schema/form จริง กำหนด implemented/pending/alias/retired อย่างมีเหตุผล รวมบริษัท/ผู้จัดทำ/หน่วย/ราคา/สถานะ ไม่ถือการจัดเอกสารนี้เป็นการลดข้อบังคับ |
| L09 | workflow local READY ไม่ใช่การยืนยันข้อมูลจริง/ล็อกโครงการ | แยก SAMPLE/UNVERIFIED/VERIFIED และ PENDING/CONFIRMED ให้ชัดก่อนเพิ่ม LOCKED ตรวจทุกต้นทุนและขอบเขต รวมรายการเพิ่มเติม ตัดสินใจโฟลว์ง่ายกับเจ้าของก่อนลงระบบรับรองจริง |
| L10 | รายงานมี Excel/print PDF แล้ว แต่ยังต้องตรวจความครบและผลลัพธ์กับงานจริง | เทียบยอดกับหน้าจอ/ข้อมูลเดียวกัน ไม่เผยต้นทุนเป็นใบเสนอราคาลูกค้าโดยไม่ตั้งใจ ทดสอบงานหลาย Keyplan และกรณีค้างข้อมูล |
| L11 | ขนาดงาน D10 ยืนยันแล้ว ยังไม่มีหลักฐาน benchmark ครบ | 20 Keyplan × 6 รายการ ตรวจเวลาเปิด/บันทึก/คำนวณ/ส่งออก ระบุเครื่อง/ข้อมูล/เวลาจริง แล้วให้เจ้าของรับเกณฑ์ก่อนนำร่อง ไม่รับรองตัวเลขเวลาล่วงหน้า |
| L12 | หลักฐานตรวจ / และ /trial.html เป็นคนละแอป | ทำ acceptance checklist ของหน้าหลักจริง ไม่ใช้การผ่านในต้นแบบแทนหลัก ทดสอบปิดเปิดใหม่/DB busy/ข้อมูลไม่ครบ/กู้คืนผิดรูปแบบ/แก้พร้อมกันในเครื่อง |
| L13 | โค้ดล่าสุดในเครื่องมีงานหลังการอัป GitHub รอบ 121 tests | รอบนี้ไม่ commit/push อัตโนมัติ เมื่ออนุมัติส่งรุ่นให้ตรวจ diff/tests/สถานะและ scan ความลับใหม่ก่อนอัป ไม่ถือ GitHub ตรงกับเครื่องเสมอ |

ลำดับแนะนำ: L01–L06 เป็นรอบถัดไป → ตรวจ L08/L10/L12 ควบคู่ → L07/L09/L11 ก่อนนำร่อง งานแท็กกับ undo ต้องไม่เปลี่ยนสูตรหรือเงื่อนไขที่ยังรอธุรกิจ

## 3. ต้องได้ข้อมูล/คำตัดสินจากเจ้าของก่อนปิดงานจริง
| รหัส | สิ่งที่รอ | เงื่อนไขการปิด |
|---|---|---|
| B01 = D03 | PN01/ED01/LB01 รวมอะไร ไม่รวมอะไร | รายการ/หลักฐานขอบเขตที่ตรวจแล้ว ไม่เดาซ้ำของในชุด |
| B02 = D04 | เศษจริงแต่ละวัสดุและการแก้ค่า | กติกาชัด พร้อมตัวอย่างตรวจยอด |
| B03 = D05 | ขนส่ง/งานส่วนกลาง/เกณฑ์เฉลี่ย | เลือกแนวทางและลงต้นทุนให้ตรวจย้อนกลับได้ |
| B04 = D09 | ราคา สกุลเงิน ภาษีที่รวม/ไม่รวม ส่วนลด ขั้นซื้อ วันที่มีผล | มีข้อมูลจริงที่ระบุเงื่อนไข ไม่แปลง VAT เอง |
| B05 = V01–V04 | Index ฟังก์ชัน/ขนาด/LED ราคาโรงงาน ขอบเขตรวม/ไม่รวม และงานจริงหนึ่งชุด | ตรวจทั้งราคาและรายการซ้ำ ใช้ข้อมูลจริงกับ workflow ก่อนรับรอง |
| B06 = M01 | บัญชี/บริษัท/วัสดุ ค่าแรง Modular เดิมที่จะรักษา | บัญชีรายการผ่านตรวจและแผนย้าย/ย้อนกลับ เจ้าของอนุมัติ ไม่ลบของเดิมก่อน |

D01/D02, D06–D08 และขนาด D10 ยืนยันแล้ว ห้ามย้อนตั้งเป็นคำถามธุรกิจที่ยังไม่เคยตอบ

## 4. งานภายหลัง — ยังไม่อนุมัติให้ดำเนินการออนไลน์
| รหัส | งาน | เกณฑ์ก่อนเปิดใช้ |
|---|---|---|
| O01 | นำแบบปัจจุบันไป Vercel/InsForge | อนุมัติแยก ออกแบบ schema ตามรุ่น local ที่ตรวจรับ ห้ามคัดลอกฐานทดลองทั้งก้อน |
| O02 | Auth บริษัท 1:1 / RLS / ownership | ทดสอบบริษัท A/B, anonymous, direct DML, RPC, ข้อมูลลูกและ backup โดยใช้ข้อมูลทดสอบ |
| O03 | VERIFIED/CONFIRMED/LOCKED ที่ server | บังคับทุกเส้นทาง API/ตารางลูก การคัดลอกเป็นร่าง/version stale และป้องกันแก้ราคาย้อนหลัง |
| O04 | ตรวจความปลอดภัย/transaction/performance บนระบบจริง | ปิดข้อเตือน advisor เดิมที่ค้างด้วยหลักฐานใหม่ ไม่ใช้ local tests แทนการตรวจ server |
| O05 | ย้ายเฉพาะข้อมูลที่อนุมัติ/สำรอง/rollback | ไม่ย้ายขยะทดลองหรือข้อมูลจริงโดยไม่มีบัญชีรายการและการยืนยัน |

ใบเสนอราคาลูกค้าสมบูรณ์ การคิดภาษี ส่วนลด สต็อก PO และสมาชิกเป็นนอก MVP ไม่ใช่งานที่ต้องแอบเติมเพื่อปิดบัญชีนี้

## 5. วิธีปิดงาน
แต่ละรายการต้องมี source/เอกสารที่แก้ กรณีทดสอบและผลจริง ข้อจำกัด และจุดตรวจร่วมกับเจ้าของ ไม่ใช้จำนวน tests รวมเพียงอย่างเดียวปิดงาน ไม่มีการถือคำว่า READY ของข้อมูล SAMPLE ว่า “ตรวจแล้ว/ใช้ราคาจริงได้”
