## 1. ข้อสรุปสำหรับเจ้าของโครงการ

**พร้อมพัฒนาต่อจากต้นแบบในเครื่อง** แนวทางหลักสอดคล้องกับมาสเตอร์เมื่ออ่านร่วมกับคำยืนยันล่าสุดของเจ้าของ: เริ่มจากงานที่ขาย → กลุ่มงาน/ชุด → วัสดุและค่าแรง เลือกซื้อหรือผลิตแยกชุด เก็บต้นทุนแยกกลุ่ม และรวมเฉพาะรายการที่ต้องจัดหาจริงตอนสรุปซื้อ

ไม่พบข้อขัดแย้งในสูตรหลักที่เป็นเหตุให้ต้องย้อนออกแบบใหม่ แต่ยังไม่ใช่การตรวจรับระบบใช้งานจริง มีข้อกำหนดที่ต้นแบบยังทำไม่ครบ โดยเฉพาะสิทธิ์และการบันทึกฝั่ง server การตรวจขอบเขตซ้ำระดับตำแหน่ง/เหตุผล หลักฐานราคาจริง และรายงานส่งออกครบตามแบบใหม่ รายละเอียดอยู่หัวข้อ 8

พบข้อความรุ่นเก่าในมาสเตอร์และเอกสารออกแบบที่อาจอ่านแล้วขัดกับหน้าจอปัจจุบัน จึงเพิ่มหัวข้อ 0.3 ใน MASTER และเชื่อมเอกสารนี้เป็นสถานะอ้างอิงล่าสุด โดยเก็บตัวอย่างเก่าไว้เป็นประวัติ ไม่เปลี่ยนสูตรธุรกิจหรือทำให้ข้อกำหนดที่ยังไม่เสร็จกลายเป็นผ่านแล้ว

รอบทบทวนนี้ตรวจไฟล์และโค้ดใน smart-boq-new รันการทดสอบและ build ในเครื่อง ไม่เรียกฐานออนไลน์ ไม่ตรวจสิทธิ์ด้วยบัญชีจริง ไม่แก้ migrations/RPC และไม่เผยแพร่เว็บ ภาพและตัวเลขเป็น SAMPLE

## 4. โครงสร้างที่ใช้พัฒนาต่อ

    BODY งานโครงตัวตู้ — BUY หรือ MAKE

## 5. กติกาคำนวณที่ยืนยันและใช้แล้ว

### ปริมาณแผงและวัสดุ

- พื้นที่แผง 1 ตร.ม. คือพื้นที่ด้านเดียว บุไม้อัด 2 ด้านใช้ไม้อัด 2 ตร.ม.
- ลามิเนตเท่ากับพื้นที่ไม้อัดด้านที่เลือกปิดผิว ไม่จำเป็นต้องปิดทุกด้าน
- ไม้โครงใช้พื้นที่แผง × อัตราเมตรไม้ต่อ ตร.ม. ที่ผู้ใช้ระบุ
- กาวใช้พื้นที่ปิดผิว × อัตราใช้ที่ผู้ใช้ระบุ ไม่เดาอัตราครอบคลุมหรือคูณสองพื้นผิวซ้ำ
- ไม่คูณพื้นที่แผงด้วยเมตรขายซ้ำ ไม่เพิ่มเผื่อเศษหรือหักช่องเอง

### ต้นทุนและราคาขาย

```text
ราคาต่อหน่วยใช้ = ราคาต่อหน่วยซื้อ ÷ ปริมาณที่ได้ต่อหน่วยซื้อ
ต้นทุนบรรทัด = ปริมาณใช้รวมเผื่อที่กรอก × ราคาต่อหน่วยใช้
ต้นทุนกลุ่ม = รวมบรรทัดคิดเงินจริง ทั้งวัสดุและค่าแรงในกลุ่ม
ต้นทุนกลุ่มต่อเมตร = ต้นทุนกลุ่มก่อนปัด ÷ เมตรขาย S001
ต้นทุนรวม S001 = รวมกลุ่มที่เปิดใช้ + ต้นทุนร่วม ครั้งเดียว
ราคาขายต่อหน่วย = ต้นทุน S001 ต่อหน่วย ÷ (1 − กำไร%/100)
ราคาขายรวม = ปริมาณขาย × ราคาขายต่อหน่วยที่ปัด 2 ตำแหน่งแล้ว
```

ใช้ Decimal ความละเอียดสูงและ HALF_UP ตามมาสเตอร์ ไม่รวมต้นทุนจากตัวเลขรายบรรทัดที่ปัดแสดงผลแล้ว กำไร 40% ของราคาขายใช้ตัวหาร 0.60 ไม่ใช้ต้นทุน × 1.40 ส่วนต่างยังไม่ใช่กำไรสุทธิ

### สินค้าชุดและค่าแรง

- CHARGEABLE คือบรรทัดคิดเงินจริง มีผลต่อต้นทุนและการจัดหา
- INCLUDED_REFERENCE คือของที่รวมแล้ว เปิดดูได้ แต่ไม่บวกต้นทุนหรือสั่งซื้อเดี่ยว
- EXCLUDED_REFERENCE คือชุดไม่รวม ต้องเพิ่มบรรทัดจริงพร้อมจำนวน หรือยืนยันว่าไม่ต้องใช้
- จำนวนอ้างอิง = จำนวนใช้ของชุดแม่ × จำนวนต่อชุดตาม snapshot ไม่คูณเมตรขายอีก ถ้าไม่ทราบใช้ null
- แรงผลิต/ประกอบและแรงติดตั้งเก็บในกลุ่มงานของตน แยก laborPhase และฐานปริมาณ อัตราต่อเมตรคูณเมตรขาย แต่ปริมาณรวมไม่คูณซ้ำ
- ราคาซื้อชุดที่ผู้ขายไม่แยกแรงผลิตเก็บเต็มในคอลัมน์วัสดุ/สินค้าชุด ไม่เดาแบ่งราคาแรงภายใน คอลัมน์ค่าแรงแสดงเฉพาะที่คิดเพิ่ม
- ของเพิ่มทับขอบเขตชุดต้องตรวจและยืนยัน เปลี่ยนจำนวน/วิธีคิด/ประเภท/ชุดแม่ต้องตรวจการยืนยันใหม่ ไม่หักหรือแก้ของเพิ่มให้เอง

### สรุปซื้อ

รวมวัสดุที่คิดเงินจริงรหัสเดียวกันจากทุกกลุ่ม/งานก่อนปัดตามขั้นซื้อ ใช้ราคาอ้างอิงโครงการสำหรับงบซื้อ คงราคาบรรทัด snapshot สำหรับต้นทุน ไม่รวม LABOR หรือรายละเอียดที่รวมในชุดเป็นวัสดุซื้อ และปริมาณเหลือเป็นเพียงค่าทฤษฎี ไม่ใช่สต็อก

ต้นแบบจับคู่ด้วย code ที่ไม่ซ้ำในทรัพยากรโครงการจำลองเดียว ขั้นฐานจริงต้องใช้ project_resource_id และตรวจเจ้าของโครงการ/บริษัท ไม่ใช้ชื่อวัสดุจับคู่

## 8. สิ่งที่ยังไม่ครบและต้องจัดการก่อนใช้จริง

| ลำดับ | สิ่งที่ยังขาด | ผลกระทบ/งานต่อ |
|---|---|---|
| A1 | ข้อความประวัติ 16/17 ตาราง วิธีผลิตทั้ง S001 และ D02 แบบเดิม | ระบุสถานะและกติกา 0.3 ให้ชัดแล้ว เก็บประวัติเพื่อย้อนตรวจได้ |
| A2 | แบบ 18 ตารางยังไม่ติดตั้งในฐาน | ต้องทำ migration, FK, UNIQUE, version, transaction, RLS และทดสอบแยกบริษัท/สถานะล็อกในระบบทดสอบใหม่ก่อน |

## 9. ลำดับพัฒนาต่อที่แนะนำ

1. ใช้ Master 0.3 + relation 18 + เอกสารนี้เป็นฐานส่งต่อ ยืนยันตัวอย่างงานจริงหนึ่งชุดพร้อมสเปกและขอบเขต ไม่เปิดหลายฟีเจอร์พร้อมกัน
2. ทำความครบของต้นแบบก่อนต่อฐาน: เหตุผล/ตำแหน่งของเพิ่ม ข้อมูลที่รอตรวจ ราคาศูนย์ การเตือนราคาต่าง และกรณีสลับวิธีที่มีค่าแรง/รายการเพิ่มอยู่แล้ว
3. เตรียม schema/migration และ RPC แบบ 18 ตารางสำหรับระบบทดสอบแยก พร้อมแผนสำรองและทดสอบย้อนกลับ ก่อนขออนุมัติลงฐาน ไม่มีการอนุมัติการแก้ฐานจากรายงานนี้
4. เชื่อมบัญชี–บริษัทและการบันทึกจริง ทดสอบ snapshot, concurrent version, lock และการปฏิเสธข้ามบริษัทบน server แล้วเทียบผลกับตัวคำนวณในเครื่อง
5. ทำรายงาน Excel/PDF จากผลเดียวกัน ตรวจทุกกลุ่มและชุดอ้างอิงให้ครบ แล้วทดลองงานจริงที่ได้รับอนุญาต เก็บข้อผิดพลาดก่อนพิจารณาเผยแพร่
