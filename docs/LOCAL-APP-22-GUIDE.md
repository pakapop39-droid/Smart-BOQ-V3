# หมายเหตุฉบับปัจจุบัน

แอปหลักปัจจุบันเพิ่มทะเบียนแท็กเป็น 24 ตารางตาม MASTER 2.1 ดู [วิธีทดลองขั้นที่ 3](TRY-STEP3.md) และ [บันทึกส่งมอบ](STEP3-DELIVERY.md) คู่มือนี้เก็บเส้นทางแกน 22 ตารางเดิมเป็นข้อมูลประกอบ ประกาศว่าแท็ก/เลิกทำยังไม่พัฒนาในข้อความเก่าเป็นสถานะก่อนรอบนี้

# ทดลองคลังรายการทำราคาต่อหน่วย — SQLite 22 ตาราง

> อ้าง MASTER 2.0 เป็นข้อกำหนดปัจจุบัน ข้อความผลตรวจ 121/124 ด้านล่างเป็นหลักฐานรอบก่อน โค้ดล่าสุดก่อนจัดเอกสารตรวจ 125 cases ผ่าน งานแท็ก/เลิกทำในหน้าหลักยังต้องเติมตาม TAG-UNDO-PLAN.md รอบนี้ไม่มีการเปลี่ยนโค้ดหรือฐาน

สถานะ: พัฒนาและทดลองใน smart-boq-new เท่านั้น ไม่เชื่อมฐานออนไลน์ ใช้เครื่องคำนวณเดิม

## วิธีใช้งาน

1. เปิด http://127.0.0.1:5177/ และกด Ctrl+Shift+R หากหน้าเก่ายังค้าง
2. เปิดเมนู **คลังรายการทำราคา** → สร้างต้นแบบ กรอกหมวด หน่วยขาย ชื่อ และกำไร ระบบสร้างรหัส RT อัตโนมัติ
3. เพิ่มกลุ่มต้นแบบตามงาน เช่น BODY / DOOR แต่ละกลุ่มเลือกซื้อสำเร็จรูปหรือผลิตเองได้ พื้นที่แผงและจำนวนชุดที่กรอกในคลังเป็น **อัตราต่อ 1 หน่วยขาย**
4. เปิดวัสดุของกลุ่ม หรือเลือกต้นทุนตรงที่ไม่ผูกกลุ่ม แล้วเพิ่มวัสดุและค่าแรงจากคลังเดิม กรอกอัตรา ตัวหาร เศษ และราคา ค่าแรงต้องระบุผลิต/ประกอบหรือติดตั้ง
5. ตรวจต้นทุนต่อหน่วย หากมีข้อผิดพลาดให้เติมข้อมูลก่อน จากนั้นกด **ตั้งเป็นพร้อมใช้** รุ่นนี้จะเก็บไว้คงเดิม ถ้าจะแก้ให้ **สร้างรุ่นถัดไป** รุ่นใหม่ยังเป็นร่างจนกว่าจะตรวจและตั้งพร้อมใช้
6. เปิดโครงการ เลือกห้องและ Keyplan ตามแบบ → **เลือกจากคลังรายการทำราคา** เลือกรุ่นที่พร้อมใช้และกรอกปริมาณตามแบบ
7. เปิดต้นทุนหรือสรุปราคา/งบซื้อได้เหมือนเดิม ชื่อและรุ่นที่มาปรากฏใต้รายการ S001 พร้อมเก็บรายละเอียดวัสดุ/ค่าแรง ราคา หน่วย ตัวแปลง และส่วนประกอบสินค้าชุดเป็นสำเนาของโครงการ

ยังสร้างรายการเฉพาะงานเองได้ ไม่บังคับให้งานเดิมเปลี่ยนเป็นต้นแบบ และไม่มีการแปลงยอดรวมงานเก่าให้เป็นอัตราต่อเมตรโดยเดา

## การคูณและการเก็บราคา

- วัสดุ/ค่าแรงแบบกรอกจำนวนเองในต้นแบบเป็นอัตราต่อหน่วยขาย นำไปใช้แล้วคูณปริมาณขายครั้งเดียว
- พื้นที่แผงรวม = อัตราพื้นที่ต่อหน่วย × ปริมาณขาย; ไม้อัด/ลามิเนตคูณด้านตามกติกาเดิม บรรทัดอิงพื้นที่ไม่คูณเมตรขายซ้ำ
- จำนวนชุดสินค้าสำเร็จรูปต้องเป็นจำนวนเต็มตามกติกาเดิม ถ้าการคิดตามเมตรทำให้เป็นเศษชุด ระบบจะรอแก้ข้อมูล ไม่ปัดหรือเดาจำนวนชุดให้
- เปลี่ยนปริมาณขายในโครงการ: กลุ่มที่ยังอิงอัตราปรับใหม่จากอัตราต้นทาง ไม่คูณยอดรวมเดิมทบ ถ้าแก้พื้นที่/จำนวนกลุ่มเป็นยอดจริง ระบบเก็บยอดจริงนั้นไว้และแจ้งในหน้ารายละเอียด
- เปลี่ยนสเปก/ราคา/กำไรเฉพาะโครงการได้ โดยแสดงว่าปรับเฉพาะงานแล้ว การเปลี่ยนหน่วยรายการที่มาจากต้นแบบต้องสร้างรายการใหม่เพื่อกรอกปริมาณตามหน่วยใหม่
- ราคาต้นทุนของบรรทัดเป็น snapshot รุ่นที่เลือก ราคาคลังที่เปลี่ยนและรุ่นใหม่ไม่ทับโครงการเดิม
- ราคางบซื้อของ project_resources ที่มีอยู่แล้วคงเดิม อาจต่างจากราคาต้นทุน snapshot ได้ ให้ตรวจทั้งต้นทุนและงบซื้อก่อนใช้งาน ไม่อัปเดตตามต้นแบบเงียบ ๆ
- ของที่รวมในสินค้าชุดไม่คิดเงินหรือซื้อแยกซ้ำ ของที่ไม่รวมต้องเพิ่มหรือยืนยันไม่ต้องใช้ ของที่ยังไม่ทราบยังเป็นรอทบทวน
- รายการเพิ่มนอกชุดต้องตรวจเหตุผลและตำแหน่งจริงในโครงการ การตั้งต้นแบบพร้อมใช้ไม่ใช่การยืนยันพื้นที่ใช้งานจริงทุกโครงการ
- รวมวัสดุที่ใช้จริงจากทุก Keyplan ตามทรัพยากรโครงการก่อนปัดขั้นซื้อ ค่าแรงแยกจากงบซื้อวัสดุ
- หยุดเลือกใช้รุ่นเก่าได้โดยไม่ลบราคาโครงการที่ใช้อยู่ รุ่นใหม่เลือกใช้กับรายการใหม่ได้ ส่วนการเปลี่ยนรุ่นให้รายการโครงการเดิมแบบเปรียบเทียบยังไม่ได้ทำ จึงไม่อัปเดตอัตโนมัติ

## บันทึกรายการในโครงการเป็นต้นแบบ (เพิ่มล่าสุด)

ในตารางรายการทำราคา กด **บันทึกเป็นต้นแบบ** หรือเปิดต้นทุนแล้วกด **บันทึกเป็นต้นแบบในคลังกลาง** กรอกชื่อต้นแบบ ระบบสร้างรหัส RT อัตโนมัติ ระบบสำเนาเป็น DRAFT พร้อมกลุ่ม BUY/MAKE วัสดุ ค่าแรง ราคาที่ใช้จริง snapshot ชุดแม่/รายละเอียด และขอบเขตตรวจซ้ำ โดยไม่แก้รายการต้นทางหรือราคาคลังวัสดุ และไม่ต้องกรอกต้นทุนใหม่

ใช้ปริมาณขายต้นทางเป็นฐาน: อัตรา PER_UNIT คงเดิม; บรรทัด MANUAL/TOTAL ปรับตัวหารด้วยปริมาณต้นทาง; พื้นที่แผงและจำนวนกลุ่มหารปริมาณต้นทางเป็นอัตราต่อหน่วย เก็บ 6 ตำแหน่งแบบ HALF_UP และแสดงหมายเหตุหากต้องปัด อัตราที่เกิดจากการสำเนาต้องตรวจในร่างก่อนพร้อมใช้ ไม่เปลี่ยนสูตรคิดต้นทุนหรือสูตรกำไร

จำนวน Modular/ชุดสำเร็จรูปที่เป็นยอดจริง อาจกลายเป็นเศษชุดเมื่อหารต่อเมตร ทำให้ยังตั้งพร้อมใช้ไม่ได้จนกว่าจะทบทวน ยอดเหมาตลอดงานและตำแหน่งเพิ่มนอกชุดต้องตรวจว่าเหมาะกับการใช้ซ้ำหรือไม่ หลักฐานยืนยันรายการเพิ่มของโครงการเดิมไม่ถูกคัดลอกเป็นการยืนยันให้โครงการใหม่

รหัสคลังซ้ำไม่ถูกทับ ข้อมูลโครงการที่เปลี่ยนระหว่างเปิดหน้าต่างจะถูกตรวจ version ถ้าผิดพลาดจะย้อนกลับทั้งการสำเนา ปริมาณต้นทางศูนย์หรือไม่ครบยังสำเนาเป็นอัตราไม่ได้ ระบบแจ้งให้แก้ปริมาณก่อน

ทดลองหน้าเว็บจาก RATE-TRY-001 รายการ 3 ตร.ม. เป็น RT-CAPTURE-SAMPLE รุ่นร่าง 1 แล้ว ตรวจได้ต้นทุน 3,000 บาท/ตร.ม. ขาย 5,000 บาท/ตร.ม. ข้อมูลโครงการเดิมยังรุ่น 4 และยอดเดิม 15,000 บาท ชุดทดสอบล่าสุด 124 รายการผ่าน และ build ผ่าน ดู artifacts/rate-capture-tests.txt และ artifacts/rate-capture-build.txt


## รหัสต้นแบบ RT อัตโนมัติ (ล่าสุด)

ทั้งสร้างต้นแบบใหม่และบันทึกรายการจากโครงการไม่ต้องกรอกรหัส ระบบใช้ลำดับเดียวกันต่อบริษัท RT001, RT002 … ต่อจากเลข RT สูงสุดที่มีอยู่ และเก็บลำดับไว้ในข้อมูลบริษัทเดิม ไม่เพิ่มตาราง รหัสเดิมทุกแบบยังคงเดิม การแก้ชื่อไม่เปลี่ยนรหัส และการสร้างรุ่นถัดไปเพิ่มเฉพาะเลขรุ่นภายใต้รหัสเดิม การลบต้นแบบไม่ทำให้ใช้เลขที่ออกแล้วซ้ำ การบันทึกผิดพลาดย้อนกลับลำดับทั้งชุด

ทดลองหน้าเว็บ: สร้างใหม่ได้ RT001 และบันทึกจาก RATE-TRY-001 ได้ RT002 โดยรหัส RT-SAMPLE-001 / RT-CAPTURE-SAMPLE เดิมคงเดิม ชุดทดสอบ 125 รายการผ่าน และ build ผ่าน ดู artifacts/auto-rt-tests.txt, artifacts/auto-rt-build.txt และ artifacts/auto-rt-codes.png
