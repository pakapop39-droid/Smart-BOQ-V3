# ใช้แบบ A ที่ยืนยันแล้วในแอปหลักในเครื่อง

คุณต๋องยืนยันตัวอย่างตู้เตี้ยที่พอร์ต 5188 และให้ใช้รูปแบบเดียวกันในแอปหลักพอร์ต 5177 โดยเก็บข้อมูลเดิม ไม่เชื่อมออนไลน์

## ผลตรวจและขอบเขต

หน้าตัวอย่างและแอปหลักเรียก `web/local-rate-workspace.mjs` ชุดเดียวกันอยู่แล้ว จึงใช้ตารางเปิดทีละชั้น เส้นทาง และย้อนกลับได้เหมือนกัน ไม่ต้องย้ายต้นแบบ SAMPLE หรือฐานตัวอย่างเข้าแอปหลัก และไม่ต้องสร้างหน้าจอซ้ำอีกชุด รอบนี้แก้การอ่านข้อมูลเดิมที่เก็บ group_id/parent_id ว่างเป็นข้อความ ให้แสดงในต้นทุนตรงเหมือน null โดยไม่เขียนข้อมูลกลับ พร้อมยืนยันการใช้ในแอปหลักและปรับเอกสารสถานะ ไม่เปลี่ยนสูตร โครงสร้างฐาน หรือข้อมูลผู้ใช้

เปิด http://127.0.0.1:5177/#rates แล้วรีเฟรชหน้า คลิกชื่อรายการหรือ **เปิดส่วนประกอบ** → คลิกส่วนประกอบ → ตารางวัสดุ/ค่าแรง → ของในชุดถ้ามี แผงขวาใช้ปุ่มแก้ข้อมูลเท่านั้น

รายการเดิมที่ไม่เคยแบ่งกลุ่มแสดง **ต้นทุนตรง (ไม่แยกกลุ่ม)** เป็นทางเข้าตารางเดิม ไม่สร้างตัวตู้/หน้าบาน ไม่เดาขอบเขตต้นทุน และไม่ย้ายบรรทัดให้เอง ต้นแบบร่างเพิ่มส่วนประกอบผ่านปุ่มที่มีอยู่ได้ ส่วนรุ่นพร้อมใช้ต้องสร้างรุ่นถัดไปก่อนแก้ คงกติกา snapshot

## ผลตรวจรอบส่งแอปหลัก

- โหลดแอปหลักใหม่ ตรวจหน้าคลัง ปุ่มเปิดส่วนประกอบ รายการร่างและพร้อมใช้
- ตรวจ RT003 → ต้นทุนตรง → ตารางต้นทุนในพื้นที่หลัก พร้อมเส้นทางและปุ่มย้อนกลับ ไม่มี drawer เปิดแทนตาราง
- ตรวจ RT-SAMPLE-001 รุ่น 1 แสดงต้นทุนหินเดิมครบหลังรองรับช่องอ้างอิงว่าง ต้นทุน 3,000.00 ขาย 5,000.00 บาท/ตร.ม. คงเดิม
- ทดสอบรวม 184/184 และ build ผ่าน เพิ่ม regression test สำหรับข้อมูลอ้างอิงว่างแบบเดิม/ใหม่และแถวลูกโดยยืนยันไม่แก้ข้อมูลต้นทาง
- เปรียบเทียบ API state ก่อน/หลังและผลคำนวณโครงการเดิมทั้ง 4 โครงการ ไม่เปลี่ยน เพิ่มเติมหลักฐานใน `artifacts/rate-a-main-accepted/`
- การยืนยันนี้รับรูปแบบ A ของคลังราคาขาย ไม่ใช่รับรองราคา SAMPLE หรือปิดงานทดสอบทั้งโครงการ งานอื่นใน BACKLOG ยังอยู่

ไม่มีการนำตัวอย่างตู้เตี้ยเข้าแอปหลัก ไม่มีการเชื่อม InsForge, deploy หรือ push GitHub
