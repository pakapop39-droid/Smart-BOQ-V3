# Smart BOQ V3 — มาสเตอร์ปัจจุบัน
ฉบับ 2.1 · ปรับปรุง 24 ตุลาคม 2569 · สถานะ: ขั้นที่ 3 ในเครื่อง 24 ตาราง รอเจ้าของทดลองรับรูปแบบ

## 1. วิธีใช้และอำนาจของเอกสาร
เอกสารนี้เป็นมาสเตอร์ฉบับปัจจุบันของ smart-boq-new รวมกติกาจากฉบับสะสม 1.9 และ 2.0 พร้อมคำอนุมัติให้พัฒนาขั้นที่ 3 ต่อเนื่องในเครื่อง อ่านคู่กับ [แบบระบบปัจจุบัน](DESIGN.md), [บัญชีงานตกค้าง](BACKLOG.md) และ [แผนแท็ก/เลิกทำ](TAG-UNDO-PLAN.md)

ลำดับใช้ข้อกำหนด: คำยืนยันล่าสุดของเจ้าของ → มาสเตอร์นี้ → เอกสารรายละเอียดที่อ้างในหัวข้อที่เกี่ยวข้อง เอกสารประวัติใช้ตรวจที่มา ไม่ใช้สั่งพัฒนาทับฉบับนี้ ข้อเสนอในแผนไม่กลายเป็นข้ออนุมัติด้านราคา สิทธิ์ หรือการเพิ่มตารางโดยอัตโนมัติ

สี่สถานะต้องแยกกัน: ยืนยันกติกาแล้ว / มีโค้ดในเครื่องแล้ว / ยังต้องพัฒนา / รอข้อมูลหรือตัดสินใจ ผล tests ไม่เท่ากับรับรองราคาจริงหรือพร้อมเปิดใช้ออนไลน์ รอบขั้นที่ 3 นี้เปลี่ยนเฉพาะแอปและ SQLite ในเครื่องตามขอบเขตที่อนุมัติ คงสูตรเดิม ไม่อัป GitHub หรือเปิดออนไลน์

- เป้าหมายบัญชีจริงเป็น 1 บัญชี : 1 บริษัท ไม่มีสลับบริษัท ทีม เชิญสมาชิก หรือบทบาทอนุมัติหลายชั้น ในเครื่องใช้ตัวตนบริษัท/ผู้จัดทำท้องถิ่น ไม่อ้างว่ามี login/RLS แล้ว

- ข้อมูล SAMPLE แยกจากข้อมูลใช้จริง ไม่ย้าย/ลบข้อมูลเดิมหรือคัดลอก credentials โดยพลการ ข้อมูลที่ยังไม่ทราบต้องเป็นว่าง/null/PENDING ไม่สมมติเป็นราคา 0
- งานจริงยังต้องตรวจข้อมูลและงานค้างใน BACKLOG ก่อนนำร่อง ทะเบียนแท็กเพิ่มอีก 2 ตารางตามคำอนุมัติ รวม 24 ตาราง มีสำเนาก่อนเปลี่ยนโครงสร้าง ข้อความแท็กเดิมต้องตรวจ preview/ยืนยันก่อนย้าย

## 3. เส้นทางงานและรหัส
โครงการ → ห้อง/พื้นที่ → Keyplan → รายการทำราคา → กลุ่มวัตถุดิบต้นทุนถ้ามี → บรรทัดต้นทุน

1. สร้างโครงการและห้อง เลือกชื่อห้องสำเร็จรูปหรือพิมพ์เอง มีชั้น/โซนและรหัสพื้นที่อัตโนมัติ ชื่อซ้ำในชั้นเดียวกันเติมลำดับ ไม่เดามิติงานจากชื่อห้อง
2. Keyplan ใช้รหัสตามผู้ออกแบบที่ผู้ใช้กรอก เลือกห้องในโครงการเดียวกัน รหัสไม่ซ้ำทั้งโครงการ ไม่มีการบังคับสร้าง B01 อัตโนมัติ
3. รายการทำราคามีชื่อ หมวด หน่วยขาย ปริมาณ และ margin ของตน รหัส S001… สร้างภายใน Keyplan ไม่ใช้รหัสเป็นตัวตัดสินชนิดงานหรือหน่วย
4. เลือกได้ทั้งรายการจากคลังทำราคาต่อหน่วย หรือสร้างรายการเฉพาะงาน ไม่สร้างตารางฐานข้อมูลแยกตามชิ้นเฟอร์นิเจอร์
5. กลุ่มวัตถุดิบต้นทุน (ชื่อเดิม กลุ่มงาน/ชุด) เช่น ตัวตู้ หน้าบาน เลือก BUY หรือ MAKE แยกกลุ่มได้ ไม่มีสวิตช์ที่เปลี่ยนวิธีของทุกกลุ่มพร้อมกันโดยบังคับ
6. งานที่ไม่ใช้กลุ่มลงต้นทุนตรงได้ ไม่บังคับงานหิน ผนัง ซิงก์ให้เลือกวิธีผลิตตู้
7. เพิ่มกลุ่มวัตถุดิบต้นทุนโดยกรอกชื่อ ไม่กรอกรหัส ระบบออก G001, G002… ภายในรายการทำราคาหรือต้นแบบแต่ละรายการเมื่อบันทึก รหัสเดิมคงเดิมเมื่อแก้ชื่อ ไม่ใช้เลขที่ลบแล้วซ้ำ ไม่เปลี่ยน UUID/การอ้างอิงหรือสูตร ดู [บันทึกเปลี่ยนชื่อและรหัส](CHANGE-GROUPS-20261024.md)

ตัวอย่างเพื่ออธิบายเท่านั้น:

|---|---|---:|---|
| B01 เคาน์เตอร์ครัว | S001 ตู้เตี้ย | 3.50 | เมตร |
| B01 เคาน์เตอร์ครัว | S002 ท็อปหิน | 2.10 | ตร.ม. |

## 4. ปริมาณ หน่วย และการคำนวณ
### 4.1 แหล่งปริมาณ
- ปริมาณขายและพื้นที่จริงผู้ใช้กรอกตามแบบ ไม่เดาความยาว พื้นที่ ช่องเว้น หรือเผื่อเศษจากชื่อสินค้า/Keyplan
- ต้นทุนกรอกตัวตั้ง ตัวหาร เผื่อเศษ และฐาน PER_UNIT (ต่อหน่วยขาย) หรือ TOTAL (รวมทั้งรายการ)
- LM01 แบบกรอกเองเลือกได้ทั้งสองฐานตามคำยืนยันล่าสุด ไม่ล็อกเป็น TOTAL เพียงเพราะรหัส LM01
- กลุ่ม MAKE แบบแผงใช้พื้นที่แผงด้านเดียวที่กรอก × ด้านบุไม้อัด/ด้านปิดผิวที่เลือก แยกตัวตู้กับหน้าบาน ไม่คูณสองด้านเองหรือคูณด้านที่รวมไว้แล้วซ้ำ
- บรรทัดที่อ้าง PANEL_AREA / PLYWOOD_AREA / LAMINATE_AREA / GROUP_QUANTITY ใช้แหล่งปริมาณนั้นครั้งเดียว ไม่คูณเมตรขายซ้ำ เงื่อนไขอัตราไม้โครง/กาวต้องกรอกและตรวจเอง
- ในต้นแบบ อัตราต่อหนึ่งหน่วยขายคูณ quantity ครั้งเดียว เมื่อเปลี่ยน quantity ให้คำนวณจากอัตราต้นทาง ไม่ทบยอดรวมเก่า กลุ่มที่ผู้ใช้แก้เป็นยอดจริงคงยอดจริง (ACTUAL_TOTAL) และแสดงความต่างจากต้นแบบ
- สินค้าชุด/Modular ที่ใช้เป็นจำนวนจริงต้องเป็นจำนวนเต็มบวก ไม่ปัดเศษชุดเพื่อให้ผ่าน การสร้างอัตราต่อเมตรที่ทำให้เป็นเศษชุดต้องกลับไปทบทวน
- ตัวอย่างเผื่อเศษใช้ 0% ที่แก้ได้ ไม่ตั้งกฎเผื่อจริง ขนส่ง หรือเฉลี่ยต้นทุนร่วมแทนเจ้าของ

### 4.2 หน่วยซื้อกับหน่วยใช้
DIRECT หน่วยตรงกัน; COUNT ได้จำนวนต่อบรรจุ; COUNT_LENGTH = จำนวน × ความยาว; AREA = ยาว × กว้าง; VOLUME = ปริมาตร หน่วยใช้ต้องสอดคล้องมิติ และ yield ต้องมากกว่า 0 ก่อนคิดเงินจริง/ซื้อแยก อัตราครอบคลุมกาวเป็นข้อมูลการใช้งานที่ต้องตรวจ ไม่ใช่สูตรแปลงลิตรเป็นพื้นที่สากล

### 4.3 สูตรและการปัด
- ราคาต่อหน่วยใช้ = ราคาต่อหน่วยซื้อ ÷ yield
- ปริมาณใช้บรรทัด = (ตัวตั้ง ÷ ตัวหาร) × แหล่งปริมาณถ้ามี × (1 + เผื่อเศษ/100) × quantity เฉพาะ PER_UNIT
- ต้นทุนรวมดิบ = ผลรวมปริมาณใช้ × ราคาต่อหน่วยใช้ ของ CHARGEABLE ที่เปิดใช้งานเท่านั้น
- ต้นทุนต่อหน่วยขาย = ต้นทุนรวมดิบ ÷ quantity
- ราคาขายต่อหน่วย = ต้นทุนต่อหน่วยขาย ÷ (1 − margin/100); margin ตั้งแต่ 0 แต่น้อยกว่า 100 ตัวอย่าง 40% หาร 0.60 ไม่คูณ 1.40
- ใช้ Decimal ความละเอียดสูง (โค้ด local 80 หลัก) เก็บทศนิยมเป็นข้อความใน SQLite ไม่ใช้ SQLite REAL หรือ binary float เป็นแกนคำนวณเงิน
- ปัด HALF_UP ราคาขายต่อหน่วย 2 ตำแหน่งก่อนคูณ quantity แล้วปัดราคาขายรวม 2 ตำแหน่ง ต้นทุนรวมรายการปัดหลังรวมค่าดิบ ไม่รวมจากตัวเลขรายแถวที่ปัดแสดงผลแล้ว
- ยอด Keyplan/โครงการรวมยอดรายการทำราคาที่ปัดแล้ว ไม่เพิ่ม margin ซ้ำในกลุ่มหรือหัว Keyplan
- กฎ precision/ขอบเขตข้อมูลเป้าหมายระบุใน [ข้อกำหนดข้อมูลรายช่อง](DATA-REQUIREMENTS.md); การตรวจขอบเขตข้อมูลให้ครบทุกช่องเป็นงานค้าง ไม่ถือว่า SQLite ทดแทน NUMERIC ของระบบจริงโดยอัตโนมัติ

### 4.4 สรุปซื้อ
รวมการใช้วัสดุ CHARGEABLE จากทุก Keyplan ตามทรัพยากร/สเปก/หน่วยโครงการก่อนปัด: จำนวนซื้อ = ceil(ใช้รวม ÷ yield ÷ ขั้นซื้อ) × ขั้นซื้อ ค่าแรงแยกจากวัสดุซื้อ ไม่ซื้อชิ้นส่วนที่รวมอยู่ในสินค้าชุดซ้ำ

ฐานกำไรคือต้นทุนตามปริมาณใช้ ส่วนงบซื้อเต็มหน่วยแสดงแยก ไม่กระจายมูลค่าวัสดุเหลือเข้าทุกงานเอง และไม่เรียกส่วนต่างนี้ว่ากำไรสุทธิ

## 5. คลัง สินค้าชุด และ snapshot
- คลังต้นทุนกลางเก็บวัสดุ ค่าแรง อุปกรณ์ และสินค้าชุด รหัสหนึ่งหมายถึงสเปก/หน่วย/บรรจุภัณฑ์ที่แน่นอน ต่างสเปกใช้รหัสใหม่
- แยกประเภทต้นทุน MATERIAL/EQUIPMENT/LABOR/OTHER ออกจากชนิด ITEM/BUNDLE/SERVICE หมวดงาน cost_groups และแท็กงานเป็นคนละหน้าที่
- เลือกทรัพยากรเข้าโครงการครั้งเดียวตามคู่ project/resource หลายบรรทัดอ้างร่วมกันได้ แต่แต่ละบรรทัดเก็บอัตราและราคาทุน snapshot ของตน
- แก้ราคาในคลังหรือสร้างรุ่นต้นแบบใหม่ไม่เปลี่ยนโครงการเดิม ราคางบซื้อ project_resources กับราคาบรรทัดทุนอาจต่างกัน ต้องแสดง/ตรวจ ไม่ sync เงียบ ๆ
- เปลี่ยนหน่วยหรือบรรจุที่ทำให้ความหมายเปลี่ยน ห้ามใช้ quantity เดิมย้อนหลังโดยปริยาย
- BUNDLE คิดราคาที่แม่ครั้งเดียว INCLUDED_REFERENCE ไม่คิดเงิน/ซื้อแยก EXCLUDED_REFERENCE ต้องเพิ่มจริงหรือยืนยันไม่ต้องใช้ UNKNOWN ยังค้างและไม่แปลงเป็นศูนย์
- reference ต้องอยู่ชุด/กลุ่ม/รายการเดียวกัน ไม่มีวงวนหรือข้ามบริษัท ไม่อนุญาตชุดซ้อนชุดในขอบเขตปัจจุบัน
- เพิ่มนอกชุดต้องมีเหตุผลและตำแหน่ง พร้อมตรวจขอบเขตซ้ำ เปลี่ยนแม่ จำนวน พื้นที่ หรือรายละเอียดที่ทำให้หลักฐานไม่ตรงต้องยืนยันใหม่ ไม่คัดลอกคำยืนยันจากโครงการเก่าไปเป็นการยืนยันโครงการใหม่
- ค่าแรงผลิต/ประกอบและติดตั้งแยกบทบาทอยู่ในงานของตน ถ้าราคาชุดไม่แจกแจงแรง ห้ามเดาส่วนแบ่งราคาแรงจากราคาเหมา
- VS Modular ใช้ราคาที่ผู้รับเหมาซื้อจากโรงงาน ไม่ใช่ต้นทุนผลิตโรงงาน ต้องตรวจรหัส ขนาด LED Index ราคา และของรวม/ไม่รวมจริงก่อนใช้กับงานจริง
- ตรวจขอบเขตด้วย cost_groups/coverage และตัวสินค้า ไม่ใช้เพียงชื่อหมวดตัดสินว่าซ้ำ ข้อกำหนดตรวจข้อมูล VERIFIED/CONFIRMED และการล็อกยังไม่ครบในแอปหลัก

## 6. คลังรายการทำราคาต่อหน่วย
- rate_templates เป็นงานที่ขายพร้อมรายละเอียดต้นทุน ไม่ใช่การปลอมวัสดุราคาก้อนใหม่
- มีรุ่น DRAFT / READY และหยุดเลือกใช้รุ่นเก่าได้ READY ใน local หมายถึงผ่านการตรวจคำนวณเพื่อทดลอง ไม่รับรองราคา/Index จริงหรือการล็อกโครงการ
- สร้างใหม่และบันทึกจากโครงการใช้ลำดับ RT001, RT002 ร่วมกันต่อบริษัท รหัสเดิมคงเดิม รุ่นถัดไปคงรหัสเดิม ไม่ใช้เลขที่ลบแล้วซ้ำ
- เลือกรุ่น READY เข้า Keyplan สำเนากลุ่ม ต้นทุน ของในชุด ขอบเขต ราคา และที่มารุ่นด้วย transaction ไม่อ้างคลังสดย้อนหลัง
- บันทึกงานโครงการกลับเป็นต้นแบบได้เฉพาะการสั่งของผู้ใช้ สำเนาเป็น DRAFT ก่อน อัตรา PER_UNIT คงเดิม ส่วนยอด TOTAL/พื้นที่/จำนวนรวมแปลงกลับตามปริมาณต้นทาง โดยเก็บทศนิยม 6 ตำแหน่ง HALF_UP และแจ้งเมื่อมีการปัด
- ข้อมูลเหมาทั้งงาน เศษชุด หรือพื้นที่ที่เฉพาะงานต้องตรวจอัตราก่อน READY ไม่รับรองโดยอัตโนมัติ รายการต้นทางและคำยืนยันเพิ่มนอกชุดไม่ถูกแก้/คัดลอกเป็นการรับรองงานใหม่

## 7. Excel และรายงาน
- คลังวัสดุ ค่าแรง และ VS Modular ต้อง export → แก้ → import กลับได้ มีรหัสภายในและ version จับคู่ ไม่เพิ่มซ้ำ ไม่ลบแถวที่หาย
- แถวใหม่เว้นรหัสภายใน/รุ่น; แถวเดิมตรวจตัวตนและ version; เนื้อหาเหมือนเดิมไม่เพิ่มรุ่น; conflict ต้องแก้ก่อน commit; import ทั้งชุด atomic
- มี preview ก่อนยืนยัน ไม่สร้างหน่วย/ประเภทที่ไม่รู้จักจากการสะกดเอง ไม่ยืนยันราคาจริงเมื่อ import
- tags แม่แบบ 2/3 แยกชื่อด้วยบรรทัดใหม่ ช่องว่างล้างแท็ก แม่แบบ 1 ไม่มีช่องจึงคงแท็กเดิม แอปหลักใช้ทะเบียน UUID และความสัมพันธ์กับรายการ ชื่อข้อความเป็น compatibility ไม่ใช่ตัวตนแท็ก
- การแก้คลังไม่แก้ snapshot งานเดิม Excel โครงการ/สรุปราคาและ PDF ใช้ผลคำนวณเดียวกับหน้าจอ ไม่ใช่ใบเสนอราคาลูกค้า
- แอปหลักส่งออกทั้งหมด/เฉพาะที่เลือกเป็นแม่แบบ 3 เพิ่ม resource_kind, scope_key, covered_scopes และ bundle_items_json ครอบคลุมสินค้าชุดทั่วไปและ VS Modular; เก็บข้อมูล LED/ขอบเขตไม่รวม/วันที่ราคา/ข้อมูลครอบคลุมด้วย รุ่น 1/2 ยังอ่านได้และไม่ล้างรายละเอียดที่ไม่มีคอลัมน์ใหม่
- ส่วนประกอบชุดใน JSON: [] หมายถึงเอาส่วนประกอบออกหลัง preview ช่องว่างคงรายละเอียดเดิม รหัสลูกต้องตรงกับตัวตน ห้ามชุดซ้อนชุด/ซ้ำลูก/ข้ามบริษัท ไม่สร้างข้อมูลใหม่ระหว่าง preview การรับรองราคาและขอบเขตจริงยังเป็นงานเจ้าของ
- ไม่รวม import โครงการ/Keyplan ในแม่แบบคลัง; สำรองทั้งฐานเป็นคนละฟังก์ชัน

## 8. แท็กและการเลือกจัดการหลายรายการ — ทำในแอปหลักแล้ว รอเจ้าของทดลอง
- ใช้แท็กงานชุดเดียวข้ามสามคลัง รายการหนึ่งมีหลายแท็กได้ ไม่สร้างวัสดุซ้ำ ไม่เพิ่มระดับเหนือ Keyplan
- มีทั้งหมด/ยังไม่ติดแท็ก ค้นหารหัส/ชื่อ เลือกหลายแท็กแบบตรงอย่างน้อยหนึ่งแท็ก (OR) แล้วใช้คำค้นกรองต่อ
- เพิ่ม เปลี่ยนชื่อ รวม ลบเฉพาะแท็กได้ ชื่อห้ามว่างหรือซ้ำหลัง normalize/trim ลบแล้ววัสดุ ราคา และต้นทุนโครงการยังอยู่
- ติ๊กหลายรายการเพื่อเพิ่ม/เอาแท็กออก ส่งออกเฉพาะที่เลือก และเลือกเพิ่มเข้าต้นทุนครั้งเดียว
- เลือกทั้งหมดเฉพาะแถวที่แสดงและเลือกได้ เปลี่ยนคลัง คำค้น หรือ filter ให้ล้างการเลือก การคลิกแก้ตัวเลขไม่เท่ากับเลือกแถว
- ต้นทุนลบหลายแถวพร้อมคำนวณและเลิกทำทั้งชุดได้ คืนตัวตน/ตำแหน่ง/จำนวน/ราคาเดิม ไม่สร้างชุดแม่และ reference ซ้ำ
- ขอบเขตเลิกทำรอบแรกคือการลบแท็กและลบต้นทุน ไม่ใช่ย้อนทุกการแก้ราคา/การรวมแท็ก หรือย้อนทั้งโครงการ
- ปิดใช้วัสดุที่มีประวัติอ้างอิงแทนการลบคลังทิ้ง การลบจากต้นทุนไม่ลบวัสดุในคลัง
- รอบนี้นำความสามารถดังกล่าวมาไว้ที่หน้าหลัก / โดยใช้ API/SQLite ไม่ใช้ localStorage แทนฐานหลัก ประวัติเลิกทำอยู่หลังรีเฟรช/เปิดใหม่ การแก้ข้อมูลหลังลบที่ทำให้เวอร์ชันไม่ตรงจะบล็อกการคืนเพื่อไม่ทับงานใหม่ ดู [วิธีทดลอง](TRY-STEP3.md)
- เลิกทำต้นทุนรอบแรกเฉพาะ component_cost_lines ของโครงการ ไม่รวมต้นทุนในคลังรายการทำราคา การคืนต้องผ่าน ownership/FK/version ใน transaction พร้อมคืนราคา/ตำแหน่งและของในชุด เก็บ journal ใน metadata บริษัท ไม่คืนบริษัททั้งแถวทับลำดับ RT

## 10. การเก็บข้อมูล การสำรอง และสิทธิ์
- แอปหลักเก็บใน SQLite เปิดกลับมาได้ มี backup/restore ในเครื่อง ส่งออก SMART_BOQ_LOCAL_24_V1 และรองรับไฟล์เดิม 18/22 ตาราง ตรวจ preview และสำรองก่อนแทนฐาน ชื่อ format ต้องตรงจำนวนตารางจริง ข้อมูลแท็กข้อความจากไฟล์เก่ารอยืนยันย้าย ไม่ถูกล้างหรือแปลงเงียบ
- /trial.html เป็นต้นแบบก่อนหน้า เก็บร่างในเบราว์เซอร์ เป็นพื้นที่ข้อมูลคนละชุดกับ SQLite ไม่รวม/ย้ายให้อัตโนมัติ
- การล้างร่างเบราว์เซอร์ไม่เท่ากับล้าง SQLite การคืนค่าตัวอย่างหรือ restore ต้องบอกขอบเขตและให้ยืนยัน ไม่ล้างข้อมูลเว็บอื่นหรือระบบเดิม
- เขียนหลายแถวต้อง transaction; version stale และ FK/ความเป็นเจ้าของต้องตรวจใน local API ไม่ใช้การซ่อนปุ่มเป็นความปลอดภัย
- เป้าหมายระบบจริง: auth และบริษัท 1:1, VERIFIED/CONFIRMED ก่อน LOCKED, ห้ามแก้ทุกแถวลูกเมื่อโครงการล็อก, คัดลอกเป็นร่างใหม่ได้โดยคงที่มา ทั้งหมดนี้ยังต้องพัฒนา/ทดสอบ ไม่ถือ READY ของต้นแบบเท่ากับ LOCKED
- ห้ามเก็บรหัสผ่านเป็นข้อความหรือเชื่อ company_id จาก client แทน session ฝั่ง server ในระบบจริง
- ห้ามทดสอบสิทธิ์โดยสร้างข้อมูลข้ามบริษัทในฐานจริงโดยพลการ ไม่ส่งฐาน .env credentials backup หรือข้อมูลผู้ใช้ขึ้น public GitHub
