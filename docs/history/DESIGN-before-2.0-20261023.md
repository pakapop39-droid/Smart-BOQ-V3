# แบบข้อมูลและหน้าจอสายหลัก — Relation เป้าหมาย 18 ตาราง

> **รหัสต้นแบบล่าสุด:** สร้าง RT001, RT002 อัตโนมัติร่วมกันทั้งสร้างใหม่และบันทึกจากโครงการ คงรหัสเดิมและใช้รหัสเดียวเมื่อสร้างรุ่นถัดไป ไม่เพิ่มตารางหรือเปลี่ยนสูตร ดู [คู่มือ](LOCAL-APP-22-GUIDE.md)

> **เพิ่มการใช้งานล่าสุด:** บันทึกรายการทำราคาในโครงการเป็นต้นแบบร่างได้ พร้อมสำเนาต้นทุนและ snapshot เดิม ต้องตรวจอัตราต่อหน่วยก่อนพร้อมใช้ คงข้อมูลต้นทางและ 22 ตาราง ดู [คู่มือ](LOCAL-APP-22-GUIDE.md)

> **สถานะล่าสุด: ทดลอง SQLite 22 ตารางแล้ว** มีคลังรายการทำราคาต่อหน่วย เลือกใช้ใน Keyplan พร้อมสำเนาราคาและรุ่นเดิมของโครงการ ดู [คู่มือ 22 ตาราง](LOCAL-APP-22-GUIDE.md) ไม่เปลี่ยนเครื่องคำนวณและไม่เชื่อมออนไลน์ ข้อความเอกสารก่อนพัฒนาด้านล่างเป็นประวัติ

> **แบบเอกสารล่าสุดเพื่อทบทวน: 22 ตารางธุรกิจ** เพิ่มคลังรายการทำราคาต่อหน่วยส่วนกลาง 4 ตาราง เลือกใช้ใน Keyplan แล้วสำเนาลงโครงการ คงสูตรและ snapshot ดู [Relation 22 ตาราง](RELATION-22-RATE-TEMPLATES.md) รอบนี้แก้เฉพาะเอกสาร โค้ดและ SQLite ยัง 18 ตาราง ไม่เชื่อมออนไลน์ ข้อความเดิมที่ยังไม่รวมคลังต้นแบบเป็นขอบเขตก่อนคำยืนยันรอบนี้

> **คำยืนยันล่าสุดเรื่อง Keyplan:** ผู้ใช้กำหนดรหัสตามแบบผู้ออกแบบเอง เลือกห้องจากห้องของโครงการ กรอกชื่อ Keyplan และรายละเอียดสำหรับใบเสนอราคาภายหลัง (ไม่บังคับ) ยกเลิกการสร้าง B01 อัตโนมัติ ข้อมูลเดิมคงเดิม รหัส S001 ของรายการทำราคายังสร้างอัตโนมัติ สูตรเดิมและ local 18 ตารางไม่เปลี่ยน ยังไม่ได้สร้างระบบใบเสนอราคา

> **การกรอกห้องในเครื่อง:** เลือกห้องสำเร็จรูปหรือพิมพ์ชื่อเอง เลือกชั้น/โซนได้ สร้างรหัสอัตโนมัติและเติมเลขชื่อซ้ำเฉพาะชั้นเดียวกัน โดยคงห้องเดิมและสูตรเดิม ใช้ areas เดิม รวม 18 ตาราง ดูท้าย [คู่มือในเครื่อง](LOCAL-APP-18-GUIDE.md)

> **สถานะ local ล่าสุด:** มี SQLite 18 ตารางและหน้ากรอกข้อมูลเชื่อมกันแล้ว ดู [คู่มือและผลตรวจ](LOCAL-APP-18-GUIDE.md) เป็นการจำลองแบบในเครื่อง ไม่ใช่การติดตั้ง migration บน InsForge ข้อความรุ่นก่อนด้านล่างคงไว้เป็นประวัติ

> **สถานะล่าสุด: ทดลองรายการงาน/ชุดในเครื่องแล้ว** เลือกซื้อสำเร็จรูปหรือผลิตเองแยกแต่ละชุด เก็บวัสดุแยกกลุ่มและไม่คิดของที่รวมในชุดซ้ำ ดู [วิธีทดลองและข้อจำกัด](LOCAL-WORK-SETS-TRIAL.md) แบบเป้าหมายยัง 18 ตารางธุรกิจ ฐานจริงไม่ได้แก้ไขและยังไม่ได้เผยแพร่รุ่นนี้

> **แบบเสนอฉบับล่าสุด: รายการงาน/ชุด 18 ตารางธุรกิจ** รายละเอียดอยู่ใน [RELATION-18-WORK-SETS.md](RELATION-18-WORK-SETS.md) แต่ละชุดเลือก BUY/MAKE เอง แสดงของที่รวมในราคาชุดโดยไม่คิดซ้ำ แทนแบบแผงอย่างเดียวและสวิตช์วิธีผลิตทั้ง S001 ฐานจริงยัง 16 ตาราง โค้ดในเครื่องปรับเป็นรายการงาน/ชุดแล้วตามคำสั่งรอบถัดมา ดูสถานะทดลองล่าสุดด้านบน


> **สถานะโค้ดทดลองก่อนแบบชุด 18 ตาราง:** ตารางกลุ่มแผงเปิดวัสดุด้านล่างและเก็บบรรทัดแยกกลุ่มในเบราว์เซอร์แล้ว รวมวัสดุเฉพาะตอนสรุปซื้อ ดู [วิธีทดลองและผลตรวจ](LOCAL-PANEL-RELATION-TRIAL.md) ฐานออนไลน์ยัง 16 ตารางธุรกิจ ไม่ได้ติดตั้ง relation 17 ตาราง ข้อความที่บอกว่ายังไม่ปรับโค้ดด้านล่างเป็นสถานะก่อนรอบนี้


> **ประวัติแบบแผง:** เจ้าของให้ปรับแบบ 17 ตารางเพื่อทบทวนก่อน เพิ่มกลุ่มส่วนประกอบและเก็บวัสดุแยกกลุ่ม รายละเอียด [RELATION-17-TABLES.md](RELATION-17-TABLES.md) ฐานที่สร้างจริงยัง 16 ตารางธุรกิจ ไม่ได้แก้ฐานหรือโค้ดในรอบนี้ ส่วนสถานะขั้น 1/ฉบับ 1.7 ด้านล่างเป็นประวัติ

### ชนิดข้อมูลที่ใช้ในแบบ

| กลุ่มช่อง | ชนิดข้อมูล |
|---|---|
| PK/FK ทุกตารางธุรกิจ | UUID แบบเดียวทั้งระบบ; รหัส B01/LM01 เป็นรหัสธุรกิจ ไม่ใช่ PK |
| auth_subject | UUID อ้าง auth.users(id) ของโครงการใหม่และไม่ซ้ำ; ยังไม่อ้างว่า UUID เดิมข้ามโครงการได้เอง |
| ชื่อ/สเปก/หมายเหตุ/รหัสธุรกิจทั่วไป | TEXT; ชื่อบังคับตัดช่องว่างแล้วไม่ว่าง; รหัส normalize แบบเดียวก่อนตรวจซ้ำโดยไม่แปลความหมายสินค้า |
| ราคาและมิติทั่วไป/จำนวนบรรจุ/ขั้นซื้อ/coverage area | NUMERIC(20,6) และเงื่อนไขบวก/ไม่ติดลบตาม Master |
| quantity | NUMERIC(18,6); ศูนย์ได้เฉพาะร่าง; TOTAL จำนวนใบโมดูลาร์ต้องเป็นจำนวนเต็ม |
| margin/waste | NUMERIC(9,4); margin ตั้งแต่ 0 และต่ำกว่า 100; waste ไม่ติดลบ |
| yield_per_purchase_snapshot | NUMERIC(28,12) มากกว่า 0 |
| usage_numerator / usage_denominator | NUMERIC(20,8); ตัวหารมากกว่า 0 |
| version | BIGINT จำนวนเต็มเพิ่มโดย server; ไม่ให้ client กำหนดข้าม |
| sort_order | INTEGER ไม่ติดลบ |
| is_active/is_archived/allowed_for_sale | BOOLEAN |
| created_at/updated_at/locked_at/price_updated_at | TIMESTAMPTZ; server เป็นผู้สร้างเวลา; locked_at ว่างเฉพาะ DRAFT |
| start_date | DATE เลือกกรอก |
| group_code/scope_key | VARCHAR(40)/VARCHAR(120) ตาม Master |
| enum/status | ค่าชุดจำกัดตาม Master; ไม่รับข้อความอิสระแทนสถานะ |

การแปลงหน่วยใช้ช่องตัวเลขตามวิธีเท่านั้น ช่องที่ไม่ได้ใช้เป็น NULL ไม่ใช่ศูนย์; yield เป็นค่าคำนวณและ snapshot ไม่กรอกซ้ำสองช่อง ส่วนที่เป็นข้อมูลเลือกกรอกตาม Master ใช้ NULL ได้ ข้อมูลบังคับไม่ใช้ข้อความปลอมหรือราคา 0 เพื่อผ่านการตรวจ

### ความสัมพันธ์และการป้องกันข้อมูลผิด

- company→project→area/Keyplan→component→group (ถ้ามี)→cost_line ต้องอยู่สายเดียวกัน category/ผู้จัดทำ/ต้นทุนกลางต้องเป็นของบริษัทเดียวกัน
- กลุ่ม component_groups ต่างจาก cost_groups ที่ใช้ตรวจขอบเขต ใช้ FK คู่ group/component ป้องกันอ้างกลุ่มคนละงาน ต้นทุนตรง group NULL ได้ ห้าม unique component/resource เพราะวัสดุเดียวใช้ต่างกลุ่มได้
- cost_line อ้าง project_resource ของโครงการนั้นเท่านั้น ไม่มี resource_id ซ้ำอีกช่องให้ชี้คนละต้นทาง
- FK/unique บังคับความสัมพันธ์ในฐาน และ server ตรวจวงวนพื้นที่/สถานะโครงการ/หน่วย/ความครบก่อนเขียน ไม่อาศัยปิดปุ่มอย่างเดียว
- RLS แยกบริษัททุกทางอ่าน/เขียน รวม export แม้ไม่มี company selector ไม่เชื่อ company_id ที่ client ส่งมา
- บัญชีปิดใช้หรือบริษัทปิดใช้เข้าแก้ไม่ได้ แต่ข้อมูลผู้จัดทำเดิมยังคงอ้างอิงได้ ไม่มี flow เปลี่ยนเจ้าของ/ย้าย parent โดยตรงใน MVP
- ไม่เพิ่มตารางยอดรวม แฟ้มสูตร Option supplier quote หลายข้อ หรือประวัติใบเสนอราคาจากระบบเก่า

## การคำนวณและการบันทึก — แบบล่าสุด 18 ตาราง

- BUY/MAKE เป็นของแต่ละ component_group ไม่ใช่ทั้ง S001; คงปริมาณขายและ margin ที่ work_component
- CHARGEABLE รวมเป็นต้นทุนของชุด/งาน และเข้าแผนซื้อเมื่อเป็นวัสดุที่ต้องจัดหา INCLUDED_REFERENCE ไม่บวกเงิน/ซื้อแยก EXCLUDED_REFERENCE ยังต้องพิจารณาว่าต้องเพิ่มหรือไม่จำเป็น ไม่ถือว่าเสร็จเพียงเพราะไม่รวมในยอด
- reference คำนวณจำนวนจากบรรทัดสินค้าชุดแม่ตาม snapshot ไม่คูณเมตรขายหรือจำนวนชุดซ้ำอีกครั้ง ไม่มีราคาซื้อเดี่ยวใช้ NULL ไม่แทนด้วย 0
- สรุปซื้อรวมเฉพาะ CHARGEABLE ตาม project_resource_id ทั้งโครงการก่อนปัดซื้อ รายละเอียดที่รวมในชุดยังเปิดดูได้ แต่ไม่เข้าตัวสะสมซื้อ
- ตรวจของเพิ่มทับส่วนที่ชุดรวมอยู่ด้วย scope/แม่/ตำแหน่งและจำนวนที่ยืนยัน ไม่บล็อกเพียงเพราะรหัสวัสดุเดียวกัน ไม่อนุญาตให้เปลี่ยนข้อความเป็น EXTRA เพื่อหลบการตรวจ
- เกณฑ์ FK, version, snapshot, ความครบของข้อมูลซื้อเดี่ยว และการเปลี่ยนวิธีเฉพาะชุดใน [RELATION-18-WORK-SETS.md](RELATION-18-WORK-SETS.md) มีผลเหนือแบบเก่าในเรื่องนี้

### ข้อกำหนดเดิมของแบบ 16/17 ตารางที่คงไว้เป็นประวัติ


แบบ 17 ตารางเพิ่มการคำนวณกลุ่มแผงก่อนใช้ขั้นตอนเดิม: ใช้พื้นที่ด้านเดียว × จำนวนด้านที่เกี่ยวข้อง × อัตราของบรรทัด × เผื่อเศษ ไม่คูณเมตรขายซ้ำ เก็บแต่ละบรรทัดพร้อมกลุ่มไว้ ไม่รวมทับข้อมูลต้นทาง รวมต้นทุนทุกกลุ่มที่เปิดใช้และต้นทุนตรงเพียงครั้งเดียว ส่วนสรุปซื้อรวมปริมาณตาม project_resource_id ทั้งโครงการก่อน CEILING รายละเอียดและข้อปรับ NULL/unique ใน [RELATION-17-TABLES.md](RELATION-17-TABLES.md) มีผลเหนือข้อเดิมเรื่องคงจำนวนตาราง


ข้อเพิ่มฉบับ 1.6: คลังวัสดุ ค่าแรง และ VS Modular ต้องนำออกเป็น Excel แก้ไขและนำกลับได้ตั้งแต่รุ่นแรก รายละเอียดฟิลด์ ข้อจำกัด transaction และเกณฑ์ทดสอบอยู่ใน [CATALOG-EXCEL.md](CATALOG-EXCEL.md) เป็นส่วนหนึ่งของแบบฐานข้อมูลเฟส 2 คง 16 ตารางธุรกิจ เพิ่ม version/เวลาระบบใน cost_resources และให้ modular_products ใช้ version ของแม่ร่วมกัน ทุกทางเขียนต้องผ่านกติกาเดียวกัน ไม่แก้ snapshot โครงการย้อนหลัง

1. อ่านราคาซื้อและตัวแปลงที่เป็น snapshot ใน cost_line ไม่ย้อนใช้ราคากลางปัจจุบันแทนเอง
2. คิด PER_UNIT/TOTAL, waste ที่ระบุ และต้นทุนทุกประเภท ตามหัวข้อ 5 Master ด้วย decimal precision อย่างน้อย 28
3. หารด้วย (1−margin) แล้วปัดราคาขายต่อหน่วย half-up 2 ตำแหน่งก่อนคูณ quantity ปัดยอดงานย่อย 2 ตำแหน่ง ไม่ปัดต้นทุนแต่ละบรรทัดก่อนรวม
4. ยอด Keyplan/โครงการรวมจากยอดงานย่อยที่ปัดแล้ว สรุปซื้อรวม use ตาม project_resource ก่อน CEILING ตามขั้นซื้อ ไม่รวม LABOR ในวัสดุซื้อ
5. ทุกคำสั่งแก้ข้อมูลลูกตรวจ expected version และ lock แถว project ใน transaction ก่อนตรวจ DRAFT และเขียนแล้วเพิ่ม version
6. ล็อกใช้แถว project เดียวกับ save ตรวจ coverage/CONFIRMED/VERIFIED ครบ และไม่มี scope ชน SAMPLE/PENDING ยังล็อกไม่ได้
7. LOCKED อ่าน/ส่งออกได้ ไม่ปลดล็อกหรือแก้ลูกย้อนหลัง ต้องคัดลอกเป็นโครงการรหัสใหม่รวม snapshot/coverage
8. เปลี่ยน CUSTOM/VS_MODULAR ต้องแสดงของเดิม/ของใหม่/สิ่งที่คง ก่อนยืนยัน transaction ไม่เก็บสองวิธี active ซ้อน

ตัวอย่าง 40% และ waste 0 ใช้เฉพาะตัวเลขที่เอกสารให้ ไม่ตั้งเผื่อเศษจริงแทนเจ้าของ ความยาวขายและพื้นที่ปิดผิวหน้าบานให้ผู้ใช้กรอกเองตามแบบจริง ไม่เพิ่มสูตรวัดอัตโนมัติ

เริ่มจากรายการงาน/ชุดแล้วเปิดรายละเอียดสินค้าและวัตถุดิบ เลือก BUY/MAKE ต่างกันใน S001 เดียวได้ ตรวจหน้าบานซื้อพร้อมบานพับว่าคิดราคาเฉพาะชุด และบานพับเพิ่มนอกชุดว่าซื้อเฉพาะส่วนเพิ่ม ตรวจของไม่รวม/ไม่ทราบก่อนรับรองยอด พร้อมตรวจแม่ลูกของ reference อยู่ในชุด/งาน/บริษัทเดียวกัน เกณฑ์ตรวจเต็มใน [RELATION-18-WORK-SETS.md](RELATION-18-WORK-SETS.md)

ข้อความนี้เป็นประวัติรอบออกแบบก่อนพัฒนา ต่อมาปรับโค้ด local ตามแบบชุดแล้ว และตรวจด้วยชุดทดสอบใหม่ ดู [สรุปงานและผลทบทวนมาสเตอร์](WORK-SUMMARY-AND-MASTER-REVIEW.md) ยังไม่ติดตั้ง migrations ของแบบใหม่หรือถือว่าผ่านเกณฑ์ server


## ผลทบทวนก่อนพัฒนาต่อ

ใช้ MASTER หัวข้อ 0.3 และ [รายงานส่งต่องาน](WORK-SUMMARY-AND-MASTER-REVIEW.md) เป็นสถานะล่าสุด: แนวทางหลักพร้อมพัฒนาต่อในเครื่อง แต่มีช่องว่างก่อนตรวจรับระบบเต็ม โดยเฉพาะ coverage ระดับตำแหน่ง/เหตุผล การรับรองราคา และ server/รายงาน ไม่ยกเว้นข้อกำหนดเดิมเพียงเพราะต้นแบบผ่าน tests
