# Smart BOQ V3 — กติกาดีไซน์ UX/UI

ฉบับ 1.2 · 24 ตุลาคม 2569 · บันทึกแนวทางที่เจ้าของทดลองแล้วเพื่อใช้ร่วมทุกแชต · ภาพและรายการตรวจรับอยู่ใน [ชุดอ้างอิงดีไซน์ที่ยืนยัน](UX-UI-ACCEPTANCE.md)

## 0. ข้อตกลงที่ล็อกใช้ร่วมกัน

ใช้กติกานี้เป็นค่าเริ่มต้นของ Smart BOQ V3 จนกว่าเจ้าของยืนยันเปลี่ยน ไม่ออกแบบใหม่แทนสิ่งที่ทดลองแล้วเพียงเพราะเปลี่ยนแชต ไม่ต้องถามยืนยันกติกาเดิมซ้ำ การแก้ข้อบกพร่องและรายละเอียดภายในแนวทางนี้ทำได้ตามงานที่ได้รับอนุมัติ หากเสนอเปลี่ยนเส้นทางหลักหรือความหมายของคำสั่ง ให้อธิบายผลต่างและให้เจ้าของตัดสินใจก่อน

| รหัส | แนวทางอ้างอิงปัจจุบัน |
|---|---|
| UX01 | คลังราคาขายใช้แบบ A: ราคาต่อหน่วย → ส่วนประกอบ → วัสดุ/ค่าแรง → ของในชุดถ้ามี เปิดตารางหลักทีละชั้น มีเส้นทางและย้อนกลับ |
| UX02 | แผงขวาใช้เพิ่ม/แก้ข้อมูล ไม่แทนตารางส่วนประกอบ; คลิกแถวเพื่อเดินชั้น ปุ่มแก้เพื่อแก้ ติ๊กเพื่อเลือกหลายรายการ |
| UX03 | หน้ากระชับแบบจัดรายการอีเมล ค้นหา/กรองและแถบคำสั่งใกล้ตาราง ยอดสรุปตำแหน่งเดียว ไม่ใช้การ์ดใหญ่หรือปุ่มกระจาย |
| UX04 | ตารางต้นทุนใช้เพิ่ม–ลบ–เลิกทำ ไม่มีสวิตช์เปิดใช้/ปิดใช้รายบรรทัด เลือกต้นทุนคิดเงินจริงที่แสดงได้ทุกแถว; ของในชุดลบ/คืนตามชุดแม่ |
| UX05 | เลือกทั้งหมดเฉพาะผลที่แสดง ล้างการเลือกเมื่อเปลี่ยนตัวกรอง; คงแท็กและการจัดการหลายรายการในคลังตามขอบเขตเดิม |

| UX07 | แยกหน่วยซื้อ หน่วยใช้ และฐานหน่วยขายจริง แสดงอัตราบรรจุ/ราคาซื้อจาก snapshot เช่น ปี๊บ → ลิตร → ต้นทุนต่อผนัง 1 ตร.ม. |
| UX08 | เปลี่ยนตัวเลขแล้วคำนวณทันที ใช้แกนเดียว หน่วยยังอยู่ครบ แยกค่าร่างยังไม่บันทึก/บันทึกแล้ว/พร้อมใช้ และจัดการค่าค้างก่อนออก |
| UX09 | ทำสำเนาเป็นรายการราคาใหม่: ตั้งชื่อ รหัสใหม่ รุ่น 1 เป็นร่าง คัดลอกทุกชั้น ไม่ทำวัสดุซ้ำหรือเปลี่ยนต้นฉบับ; สร้างรุ่นถัดไปใช้รหัสเดิม |
| UX10 | เตรียมราคาในคลัง → เลือกพร้อมใช้เข้า Keyplan → กรอกปริมาณจริง คงสูตร margin/Decimal/การปัดและ snapshot ของงานเดิม |

## 1. ขอบเขตและแหล่งอ้างอิง

เอกสารนี้เป็นกติกาหน้าจอร่วมสำหรับทุกแชตที่ทำงานใน Smart BOQ V3 อ่านร่วมกับ [MASTER](MASTER.md) และ [แบบระบบ](DESIGN.md) กติกาธุรกิจ สูตร หน่วย สิทธิ์ และขอบเขตระบบใช้ MASTER ปัจจุบันเสมอ คำยืนยันใหม่ของเจ้าของมีผลเหนือเอกสารและต้องบันทึกเมื่อเปลี่ยนแนวทาง

คำยืนยันล่าสุด: คลังราคาขายต่อหน่วยใช้ **แบบ A คลิกเปิดตารางทีละชั้น** มีเส้นทางและปุ่มย้อนกลับ ไม่กางแถวซ้อนและไม่เอาตารางส่วนประกอบไปไว้ในแผงขวา ส่วนแผงขวาใช้แก้ข้อมูลของแถว และใช้ในคลังวัสดุตามที่ตกลง หลักจัดการรายการแบบอีเมลสำหรับค้นหา กรอง และติ๊กหลายรายการยังคงอยู่ การรับแนวทางไม่แทนการตรวจรับฟังก์ชันหรือการอนุมัติออนไลน์

แบบร่างประกอบอยู่ที่ `artifacts/ux-mail-proposal-20261024/index.html` และ `editor-proposal.png` เป็นไฟล์ในเครื่องที่อาจไม่มีใน checkout อื่น ไม่ใช่ข้อกำหนดสูตรหรือหลักฐานว่าพัฒนาแล้ว กติกาในเอกสารนี้ใช้งานได้โดยไม่ต้องมีภาพ

ภาพที่เก็บถาวรสำหรับแนวทางที่ทดลองแล้วอยู่ใน [ชุดอ้างอิงดีไซน์](UX-UI-ACCEPTANCE.md#ภาพอ้างอิง) และ docs/assets/ux-approved/ ใช้แทนการพึ่งไฟล์ artifacts ที่อาจหายจาก checkout อื่น ภาพเป็นตัวอย่างข้อมูล SAMPLE/ค่าร่าง ณ เวลาตรวจ ข้อความในกติกาปัจจุบันมีผลเหนือป้ายหรือยอดเก่าในภาพ

## 2. โครงหน้าจอที่ตกลงใช้

| ส่วน | กติกา |
|---|---|
| เมนูซ้าย | พับ/ซ่อนและเปิดกลับได้ แสดงหน้าที่เลือกชัด ไม่สร้างระดับข้อมูลใหม่ |
| ส่วนหัว | ชื่อหน้าหนึ่งครั้ง มีทางกลับและบริบท รหัส ชื่อ รุ่น หน่วยขาย สถานะรวมในแถวกระชับ |
| แถบคำสั่ง | รวมคำสั่งที่เกี่ยวกันไว้ติดกัน มีปุ่มหลักตามบริบท คำสั่งรองอยู่ใน `⋯` ไม่กระจายปุ่มเต็มความกว้าง |
| ค้นหา/กรอง | อยู่ใกล้ตาราง แสดงเงื่อนไขและจำนวนที่พบ มีวิธีล้างตัวกรอง |
| ตารางหลัก | เป็นพื้นที่ทำงานหลัก แถวกระชับ หัวตารางคงที่เมื่อเลื่อน ข้อความชิดซ้าย ตัวเลขชิดขวา หน่วยชัด |
| รายละเอียด | ในคลังราคาขาย คลิกรายการ/ส่วนประกอบเปิดตารางชั้นถัดไปในพื้นที่หลัก มีเส้นทางและย้อนกลับ แผงขวาใช้แก้ข้อมูลเท่านั้น ในคลังวัสดุคลิกแถวเปิดแผงขวาตามเดิม |
| ยอดสรุป | รวมต้นทุน กำไร และราคาขายในแถบล่างตำแหน่งเดียว คงมองเห็นและไม่ทับแถวสุดท้าย |

ไม่ใช้การ์ดใหญ่แทนรายการในตาราง ไม่ซ้ำยอดเดียวกันทั้งกล่องใหญ่และข้อความหลายจุด ข้อมูลทางเทคนิค เช่น จำนวนตาราง SQLite อยู่ในรายละเอียดสถานะ ใช้ป้าย LOCAL ขนาดเล็ก แต่ข้อผิดพลาดหรือข้อมูลไม่ครบที่กระทบงานต้องยังมองเห็น

คลังราคาขายแสดงส่วนประกอบเป็นแถวตาราง คลิกแล้วเปิดตารางวัสดุ/ค่าแรงของส่วนนั้น ไม่ใช้แท็บแทนชั้นส่วนประกอบ ของในชุดเปิดเป็นตารางถัดไปตามข้อมูลที่มี ต้นทุนตรงเป็นทางเข้าข้อมูลเดิม ไม่สร้างกลุ่มในฐานเอง หน้าคลังรายการทำราคายังเป็นจุดจัดราคาต่อหน่วย โครงการเลือกจากคลังแล้วกรอกปริมาณจริง ไม่ย้ายงานประกอบราคาหลักกลับไปอยู่ในโครงการ

## 3. พฤติกรรมรายการและการแก้ไข

ตารางต้นทุนต่อหน่วยต้องแยกหน่วยซื้อ/หน่วยใช้/หน่วยขายงาน: ใต้ชื่อวัสดุแสดงหน่วยซื้อ อัตราบรรจุจาก snapshot และราคาซื้อต่อหน่วยซื้อ; หัวปริมาณและต้นทุนรวมระบุฐาน 1 หน่วยขายจริง เช่น 1 ตร.ม.; ราคาต่อหน่วยใช้ระบุบาท/ลิตรหรือหน่วยของแต่ละแถว หน่วยต้องยังอยู่ครบเมื่อแสดงผลร่าง ไม่แก้สูตรหรือข้อมูลเพื่อปรับข้อความ

ในฟอร์มต้นทุนที่เลือกรายการจากคลัง มีช่องค้นหารหัส/ชื่ออยู่เหนือรายการเลือก แสดงจำนวนที่พบ ล้างคำค้นเพื่อดูทั้งหมด การกรองต้องคงวัสดุที่เลือกไว้และไม่เปลี่ยนค่าคำนวณหรือสร้างข้อมูลเอง

ตารางประกอบต้นทุนใช้เพิ่ม–ลบ–เลิกทำ ไม่แสดงสวิตช์เปิดใช้/ปิดใช้ในฟอร์มบรรทัด เลือกบรรทัดคิดเงินจริงได้ทุกแถวที่แสดง ลบเฉพาะในรายการและเก็บวัสดุในคลัง ของในชุดลบ/คืนตามชุดแม่ ดู COST-LINES-ADD-DELETE-20261024.md

- **คลิกแถวที่มีส่วนประกอบเพื่อเปิดตารางถัดไป; ปุ่มแก้ใช้แก้ข้อมูล; ติ๊กช่องเพื่อเลือกหลายรายการ** แยกกัน ในคลังราคาขาย แถววัสดุปลายทางที่ไม่มีรายการย่อยไม่เปิด drawer อัตโนมัติ ใช้ปุ่มแก้เท่านั้น ส่วนคลังวัสดุยังคลิกแถวเปิดแก้ได้ตามขอบเขตเดิม ช่องกรอก/ปุ่มในแถวต้องไม่ทำให้สลับชั้นโดยไม่ตั้งใจ
- ปุ่มหลักทุกแถวของคลังราคาขายต้องเป็น “เปิดส่วนประกอบ” ทั้งร่างและพร้อมใช้ ตารางส่วนประกอบใช้ “เปิดตาราง” ไม่วาง “แก้ข้อมูล” เป็นปุ่มหลักแทนการเปิดชั้นถัดไป การแก้ชื่อ/หน่วย/กำไรอยู่ในเมนูภายในรายการ และข้อมูลกลุ่มแก้จากภายในตารางกลุ่มนั้น
- เลือกทั้งหมดเฉพาะรายการที่แสดงหลังค้นหา/กรอง แสดงจำนวนที่เลือก เปลี่ยนแท็บหรือเงื่อนไขกรองแล้วล้างการเลือก ไม่กระทบรายการที่มองไม่เห็น
- คำสั่งหลายรายการปรากฏตามจำนวนและชนิดที่เลือก เช่น เพิ่ม/เอาแท็กออก ส่งออก ลบ ไม่เพิ่มแก้ราคา/หน่วยทั้งชุดเอง
- ก่อนลบแสดงจำนวนและผลกระทบ ลบหลายแถวแล้วเลิกทำทั้งชุดได้ คืนค่าและตำแหน่งตามขอบเขต undo เดิม แยกลบแท็กออกจากลบรายการ
- ช่องตัวเลขง่ายที่รองรับอยู่แก้ในตารางและเห็นผลทันที รายละเอียดหน่วย ตัวหาร เผื่อเศษ แหล่งปริมาณ และที่มาราคาแก้ในแผงขวา ค่าที่แสดงสองจุดใช้สถานะเดียวกัน
- แผงขวาระบุชื่อ/รหัสและบริบท เปิดข้อมูลจำเป็นก่อน ส่วนเพิ่มเติมพับได้ แต่ข้อผิดพลาดในส่วนพับต้องมีสัญญาณให้พบ
- แยกคำนวณระหว่างกรอกจากบันทึกลงฐาน แสดงบันทึก/ยกเลิกและสถานะให้ตรงพฤติกรรมจริง เมื่อมีค่าค้างแล้วเปลี่ยนแถว ปิดแผง หรือออกหน้า ต้องมีทางบันทึก/ทิ้ง/อยู่ต่อ ไม่ทิ้งข้อมูลเงียบ ๆ
- ไม่ใช้สีอย่างเดียวบอกเลือก ร่าง พร้อมใช้ หรือผิดพลาด มีข้อความ/สัญลักษณ์ ปุ่มไอคอนมีชื่อและใช้คีย์บอร์ดได้

## 4. หน่วยและการคำนวณ

- ชื่อช่องในต้นแบบคลังคือ **ปริมาณใช้ต่อ 1 หน่วยขาย** พร้อมหน่วยใช้และหน่วยขาย เช่น ไม้โครง 8 เมตรต่อผนัง 1 ตร.ม.
- แสดงการแปลงหน่วยซื้อเป็นหน่วยใช้และต้นทุนทันทีจากแกนเดิม เช่น 290 บาท/มัด ÷ 25 เมตร/มัด = 11.60 บาท/เมตร; ใช้ 8 เมตร = 92.80 บาท ตัวอย่างไม่ใช่ราคาจริงที่ตรวจรับ
- แสดงฐาน/แหล่งปริมาณให้ชัด หากมีตัวหาร เผื่อเศษ หรืออ้างกลุ่ม ต้องแสดงปริมาณหลังคำนวณ ไม่แสดงอัตราดิบเป็นยอดจริงผิดความหมาย
- ยอดสรุปใช้แกนคำนวณเดียวกับตาราง ไม่สร้างสูตรเงินใหม่หรือรวมจากตัวเลขรายแถวที่ปัดแสดงแล้ว ข้อมูลไม่ครบแสดงรอตรวจ/รอราคา ไม่แทนศูนย์
- คง margin, Decimal, การปัด หน่วย snapshot และข้อจำกัดเดิม READY ไม่เท่ากับตรวจรับราคาจริง การแก้คลังไม่เปลี่ยนราคางานเก่าเงียบ ๆ

## 5. มาตรฐานภาพเริ่มต้นและจอขนาดต่าง ๆ

ค่าเริ่มต้นสำหรับพัฒนาและตรวจภาพ ไม่ใช่ขนาดตายตัวทุกจอ: ตัวอักษรเนื้อหา 14px, แถวทั่วไป 36–40px, แถวมีช่องกรอก 40–44px, ระยะห่าง 8/12/16px, เมนูซ้ายประมาณ 180–220px, แผงขวาประมาณ 320–380px ใช้สีกรมท่า/เขียวกับพื้นกลางอ่อนตามแนวเดิม สีเข้มเฉพาะจุดสำคัญ

ปรับตามฟอนต์ไทยและความอ่านง่าย ไม่ย่อทั้งหน้าเพื่อให้พอดี ตรวจเดสก์ท็อป 1366×768 และ 1600×900 พร้อมข้อความยาว เมื่อพื้นที่ไม่พอให้พับเมนู/เปิดแผงขวาทับพื้นที่แบบปิดได้ หรือเลื่อนตารางแนวนอนโดยคงรหัส/ชื่อ/ช่องเลือกที่จำเป็น ไม่บีบคอลัมน์จนหน่วยหรือยอดอ่านไม่ได้

## 6. วิธีใช้และตรวจรับ

ก่อนส่งงานให้ใช้ [รายการตรวจรับ UX01–UX10](UX-UI-ACCEPTANCE.md#รายการตรวจรับสำหรับงานรอบถัดไป) เลือกเฉพาะส่วนที่เปลี่ยนและส่วนที่อาจกระทบ ระบุ ผ่าน/ไม่ผ่าน/ยังไม่ได้ตรวจ/ไม่เกี่ยวข้อง พร้อมเหตุผลและหลักฐาน ห้ามติ๊กว่าผ่านเพราะมีโค้ดหรือมีภาพเก่า ไม่ต้องรันทุกกรณีซ้ำสำหรับงานเอกสารล้วน

ทุกแชตอ่านกติกานี้ก่อนออกแบบหรือแก้หน้าจอ ใช้ component/style ร่วม ไม่เพิ่มชุดการ์ดหรือระยะห่างเฉพาะหน้าจนแตกต่าง ถ้างานขัด MASTER ให้ชี้ความขัดแย้งก่อน ไม่ดึงสกิลเก่ากลับมาเพิ่ม VAT ใบเสนอราคาเต็มรูปแบบ หรือสิทธิ์หลายชั้น

ก่อนส่งงาน UI ตรวจและแนบหลักฐานตามงานที่แก้:

1. เห็นตารางใกล้ส่วนหัว ไม่ต้องเลื่อนผ่านหัวเรื่อง/ยอดซ้ำ ปุ่มและหน่วยไม่ล้นหรือถูกบัง
2. ค้นหา กรอง เลือกทั้งหมด และจำนวนที่เลือกตรงกัน คลิกแถวกับติ๊กแยกกัน
3. เปิด/ปิดแผงไม่เสียบริบท จัดการค่าค้างได้ และเดินด้วยคีย์บอร์ดได้
4. เปลี่ยนตัวเลขแล้วปริมาณ ต้นทุน ยอดสรุปตรงกันทันทีตามสูตรเดิม รวมกรณีข้อมูลไม่ครบ
5. ลบ/เลิกทำตามขอบเขตที่แก้แล้วรายการ ค่า และยอดกลับถูกต้อง งานเดิมยังคง snapshot
6. บันทึกภาพหน้ารายการและรายละเอียดตามขนาดจอที่ตรวจ ระบุว่าอะไรเป็นแบบร่าง มีโค้ดแล้ว หรือรอเจ้าของทดลอง

สถานะฉบับ 1.2: เจ้าของยืนยันแบบ A จากตัวอย่างตู้เตี้ยและยืนยันว่าทดลองทำสำเนาใช้ได้ พร้อมสั่งบันทึกกติกาที่ทดลองแล้วเพื่อใช้ร่วมกัน รอบบันทึกนี้แก้เฉพาะเอกสาร/สกิลและจัดเก็บภาพเดิม ไม่แก้แอปหรือฐานข้อมูล ไม่ถือเป็นการอนุมัติปรับทุกหน้า เชื่อมออนไลน์ หรือเผยแพร่
